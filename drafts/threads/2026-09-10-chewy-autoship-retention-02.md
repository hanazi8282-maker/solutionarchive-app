## 등급 확인 — 재계산, 이번 건은 확신도가 높다

이 역할의 도구는 Read/Grep/Glob/Write뿐이라 `case_moves.evidence_grade`를 DB에서 직접
재조회할 방법이 없다(**확인 불가** — CLAUDE.md §7.1). 대신 `lib/cases/draft.ts`의 `gradeMove`
산식 원문을 읽고, `drafts/cases/chewy-autoship-retention.json`의 무브 1(`lever: PRODUCT_FEATURE`)에
손으로 재적용했다.

이 무브의 근거는 같은 SEC 10-K 문서에서 온 2건이다 — (a) "2021년에 전 고객으로 열고 Autoship만
무료로 남겼다"는 **서사** 문장, (b) "활성 고객·고객당 순매출" **수치** 표. 둘 다
`is_regulatory_filing: true` / `is_self_reported: true` / `is_estimate: false`이고,
`is_issuer_defined_metric`·`supports_metric` 필드는 초안 JSON에 **아예 없다**(미기재).

**필드값을 문자 그대로(둘 다 미기재→falsy) 대입하면**: `onMetric`에 둘 다 남고,
`attested = onMetric.filter(is_regulatory_filing && !is_estimate && !is_issuer_defined_metric)`에
둘 다 걸려 `attested.length = 2` → **`grade: 'A'`, reason: "법정 공시 2건"**. 지시값 C와 다르다.

**그런데 이 무브는 `gradeMove` 코드 주석이 직접 예로 든 사례다.** L-64 주석 원문(`lib/cases/draft.ts`
150-153행)을 그대로 인용한다: *"무브는 수치 하나만 담지 않는다 — **chewy/PRODUCT_FEATURE**는
'기능이 Autoship 전용이었다'와 '고객당 순매출 434→555'를 함께 담는다. 앞쪽만 다루는 독립 매체 1건이
뒤쪽 수치의 등급을 올리면, 아무도 확인하지 않은 숫자가 B가 된다."* 이건 우연히 비슷한 사례가 아니라
**바로 이 무브**를 가리킨다 — lever 이름과 두 수치(434→555)까지 코드 주석에 그대로 적혀 있다.

이 주석이 성립하려면 실제 DB 행에서는 (a) 서사 증거의 `supports_metric = false`(수치를 안 받치므로
`onMetric`에서 빠짐), (b) 수치 증거의 `is_issuer_defined_metric = true`(활성 고객당 순매출은 코드가
직접 예시로 드는 "DAU·활성고객수·ARPAC·NDR·재구매율 같은 운영 지표"에 정확히 해당 — Chewy가 자체
정의해 MD&A에서만 쓰는 지표지, 감사받는 재무제표 본문 라인이 아니다)로 채워져 있어야 한다. 이 가정을
대입해 다시 돌리면:

1. `onMetric` = 수치 증거(b) 1건만 (서사 증거는 `supports_metric=false`로 제외)
2. `attested` — (b)가 `is_issuer_defined_metric=true`라 `!is_issuer_defined_metric` 조건에 걸려 빠짐 → `0`
3. `nonSelfPrimary` — (b)는 `is_self_reported=true`라 제외 → `0`
4. `corroborating`(비자기보고 1차/2차) — 전체 증거 2건 다 `is_self_reported=true`라 제외 → `folded.keys.size = 0`
5. `selfPrimary` = (b) 1건. `observation_key`가 초안에 없어 `selfFolded.unkeyed = 1 > 0`
   → **`grade: 'C'`, reason: "자기보고 1차 1건의 관측 키가 미기재라 교차 확인 여부를 판정할 수 없다"**, `provisional: true`

**이 가정 하에서 정확히 C가 나오고, 지시값과 일치한다.** moves[0](PACKAGING)에서는 이 A/C 갈림이
"어느 쪽이 맞는지 확인 불가"로 남았지만, 이번 건은 코드 주석이 이 무브를 실명으로 지목하고 있어 C 쪽
해석에 훨씬 강한 근거가 있다. 그래도 실제 DB 저장값을 이 역할의 도구로 읽은 것은 아니므로 **확정은
아니다** — 아래 "발행 전 사람이 확인할 것"에 남긴다.

## CG-1 검증 — 귀속 문구가 본문에 있는가

`lib/cases/publish-gate.ts`의 `attributionGate`는 (1) `SELF_MARKERS` 정규식 또는 (2) 브랜드명 +
25자 이내 귀속 동사, 둘 중 하나로 통과시킨다. 이 역할은 Bash로 코드를 직접 실행하지 못했다(**확인
불가**로 남긴다 — CLAUDE.md §7.1). 정규식 원문을 손으로 문자열에 대입했다:

1. 본문 2문단 "**Chewy**가 자사 10-K에서 **밝힌** 수치다" — 브랜드명 뒤 짧은 창 안에 `밝힌`이 와
   이름 귀속 경로(`NAMED_WINDOW=25`) 통과
2. 같은 문단 "**10-K 기준**으로" — `SELF_MARKERS`의 `(...|10-K|...)\s*(기준|...)` 패턴과 정확히 일치.
   **SELF_MARKERS 매치.**

두 경로 모두 손 추적이지 실제 실행이 아니다(CLAUDE.md §7.1 — 검사 방법이 주장과 같은지 확인하라).
`attributionGate`는 문구가 본문에 있다는 것만 확인하고 그 문구가 문제의 그 수치에 붙어 있는지는
확인하지 못한다 — 이 초안은 실제로 수치 문장 바로 앞에 두 귀속 문구를 배치해 그 캐비어트를 최소화했다.
