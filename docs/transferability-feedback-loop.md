# 이식성 피드백 루프 — 하루치를 모아 다음 조사에 되돌린다

작성 2026-09-23. 구현 브랜치 `feat/grade-card-context-loop`.

## 1. 고치려는 것

채점 카드(`/cases/grade`)에는 이식성 `select` 만 있었다. 사람이 LOW 를 고르는 순간
**왜 낮은지는 사람 머릿속에서 끝났다.** 그래서 다음 밤 조사가 같은 종류의 옮길 수 없는
사례(자체 공장, 임상, 규제 업종, 연 매출 수백만 달러 전제)를 또 주워 왔다.

루프가 끊긴 지점은 정확히 한 곳이다: **판정 이유를 담는 자리가 없었다.**

## 2. 자리 3개

| 자리 | 무엇 | 파일 |
|---|---|---|
| 입력 | LOW/MEDIUM 을 고르면 나타나는 이유 칸(200자, 필수 아님) | `app/cases/grade/grade-card.tsx` |
| 저장 | `case_moves.transferability_reason` · `..._reason_at` | `supabase/migrations/20260930000005_transferability_reason.sql` |
| 출력 | 하루치 `.md` + 최근 14일 `latest.md` | `scripts/transferability-feedback-digest.mjs` → `ops/state/transferability-feedback/` |

`_at` 이 따로 있는 이유: `reviewed_at`(승인 시각)으로 세면 **옛 승인에 오늘 붙인 사유**가
영영 집계되지 않는다. 다이제스트가 "어제 적힌 사유"를 고르는 기준은 사유 시각이다.

## 3. 왜 매 건 즉시가 아니라 하루치인가

사유 1건은 표본이 아니라 일화다. 즉시 반영하면 어제 한 사람이 적은 한 줄이 오늘 조사
방향을 통째로 돌린다. 하루 모으면 반복되는 제약이 보이고 한 건짜리 변덕은 묻힌다.

그래서 리듬이 이렇다.

```
사람 채점(수시) → transferability_reason 누적
   → 다이제스트 크론 KST 06:04 (1일 1회) → ops/state/transferability-feedback/<날짜>.md + latest.md
      → 다음 daily-cmo-loop(KST 05:17)의 케이스 조사 프롬프트가 latest.md 를 Read
```

`daily-cmo-loop` 가 다이제스트보다 **앞선 시각**이라, 그날 조사는 전날 판 `latest.md` 를
읽는다. 의도한 것이다(하루 단위 루프). 지연을 없애야 하면 워크플로 cron 을 19:50 UTC 로
당기면 된다 — 한 줄이다.

## 4. 배선은 한 곳

`scripts/cmo-daily.mjs` 의 `researchPrompt()`. 케이스 조사 프롬프트를 조립하는 유일한
자리다(초안 쓰기는 `writerPrompt()`, 발굴은 `scripts/discovery-run.mjs` — 둘 다 아니다).

프롬프트에 들어가는 문구는 **"최근 이식성 반려 사유(참고, 규칙 아님)"** 다. 금지 목록이
아니다. 조사원이 이걸 규칙으로 읽으면 제약이 있는 사례를 전부 피하게 되고, 그러면
"자본이 필요한 무브는 존재하지 않는다"는 왜곡된 아카이브가 된다. 파일이 없으면 이 줄을
아예 넣지 않는다 — 없는 파일을 Read 하라고 시키면 조사원이 그걸 실패로 보고한다.

## 5. 미적용·0건·확인 불가를 가른다 (§7.1)

| 상황 | 동작 |
|---|---|
| 마이그 20260930000005 미적용 | 카드는 이유 칸을 그대로 보여 주고 저장 시 그 필드만 빼고 저장. 결과 메시지에 `이유는 저장 안 됨(마이그 20260930000005 미적용)`. 다이제스트는 **종료코드 2**, 파일 쓰지 않음 |
| 마이그 20260930000004(D 트랙) 미적용 | `pmf_signal`·`metric_kind` 만 빠지고 저장. 메시지에 `S·지표종류는 저장 안 됨(…)` |
| 그날 사유 0건 | `<날짜>.md` 에 **`0건`** 을 본문으로 적는다. 파일 없음과 구분된다 |
| DB 조회 실패 | 종료코드 2. 파일 쓰지 않음 |

0건 파일을 쓰지 않으면 다음 사람이 "파일이 없네"와 "사유가 없었네"를 구분할 수 없다.
거꾸로 컬럼이 없을 때 0건 파일을 쓰면 **확인 실패가 음성으로 접힌다** — 그래서 한쪽은
쓰고 한쪽은 안 쓴다.

## 6. 검사

- `node scripts/transferability-digest-selftest.mjs` — 집계 순수함수(날짜 이동·KST 경계·
  0건 표기·누락 필드·latest 합계) 17건. 워크플로가 다이제스트 **전에** 돌린다.
- 날짜 경계가 하루 밀려도 파일은 "0건"으로 멀쩡해 보인다. 그게 이 검사가 있는 이유다.

## 7. 아직 안 한 것

- 사유를 낱말로 묶어 "가장 흔한 제약 3개"를 뽑는 집계. 지금은 원문 나열이다 —
  건수가 30건을 넘으면 프롬프트가 길어지므로 그때 넣는다.
- `discovery-run.mjs`(발굴) 쪽 배선. 발굴은 "이 브랜드를 볼까"를 정하는 단계라
  이식성 판정이 붙기 전이다. 케이스 조사 프롬프트 한 곳만 배선했다.
