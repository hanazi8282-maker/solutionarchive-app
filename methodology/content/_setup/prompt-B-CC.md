# Claude Code 전달용 — 프롬프트 B-CC (평가 하니스 구축)

> **주의**: 이건 남헌이 직접 푸는 프롬프트 B와 **다른 것**이다.
> 프롬프트 B = 사람의 판정 능력 측정 (용도 ①)
> **프롬프트 B-CC = `content-gate` 스킬 품질 측정 (용도 ②)** — 재실행 가능한 하니스
>
> 두 결과는 서로 대체하지 않는다. 스킬 점수가 높아도 사람이 못 풀면 D(역방향) 대상 선정을 못 한다.

```
methodology/content/eval-set.md 로 content-gate 스킬의 평가 하니스를 만들어줘.
일회성 응시가 아니라 스킬을 고칠 때마다 재실행할 수 있는 구조여야 한다.

## 왜 만드는가

지금은 스킬을 수정해도 좋아졌는지 나빠졌는지 알 방법이 없다.
그런데 eval-set.md 에는 정답이 이미 알려진 30문항이 있다 — 두 원문의 실측 대조
사례에서 뽑았고, 왜 그런지까지 원문이 분석해두었다.

이걸로 스킬 점수를 내면 수정 전후를 정량 비교할 수 있다.
skill-creator 가 말하는 eval 과 같은 구조인데, 결정적으로 다른 게 하나 있다:
**문항을 우리가 만든 게 아니라 원문이 정답과 함께 제공했다.**

## STEP 1 — 문항/정답 물리 분리 (INF-04 해소)

현재 eval-set.md 한 파일에 §2 문항과 §3 정답이 같이 있다.
"정답 미리 보지 마"라고 지시해도 **파일을 통째로 읽으면 이미 본 상태**가 된다.
물리적으로 막아야 한다.

  methodology/content/eval-set.md              ← 유지 (설명·사용법·확장 방법)
  methodology/content/eval/questions.md        ← §2 문항 30개만
  methodology/content/eval/answers.md          ← §3 정답 + §4 채점표

eval-set.md 는 §2·§3·§4 자리에 "→ eval/questions.md" "→ eval/answers.md" 포인터만 남겨.
§0·§1·§5(용도·사용법·확장)는 그대로 둔다.

⚠️ answers.md 는 .claude/skills/content-gate/references/ 에 **절대 넣지 마.**
   스킬이 정답을 먼저 보면 평가 자체가 무의미해진다.

## STEP 2 — 평가 러너

scripts/run-eval.mjs (또는 리포 컨벤션에 맞는 확장자)를 만들어줘.

동작:
  1. eval/questions.md 에서 문항 30개를 파싱
  2. 각 문항을 content-gate 스킬이 로드된 **깨끗한 컨텍스트**에 하나씩 던진다
     - answers.md 는 절대 컨텍스트에 넣지 않는다
     - 이전 문항의 답변도 넣지 않는다 (문항 간 오염 방지)
  3. 응답에서 [선택]과 [근거]를 추출
  4. eval/answers.md 로 채점
  5. eval/results/YYYY-MM-DD-<commit>.md 에 결과 저장

채점 규칙 (eval-set.md §2 그대로):
  - 각 문항 2점 = 선택 1점 + 근거 1점
  - 근거는 **표현이 달라도 같은 규칙을 지목했으면 정답**
    (예: 정답이 "R-11 / 표본 이론"인데 응답이 "타깃을 좁혀서"라고 했으면 정답)
  - ★ **선택 O / 근거 X** 를 따로 카운트한다 — 우연히 맞힌 것이라 재현되지 않는다
  - 만점 60점

## STEP 3 — 결과 리포트 포맷

eval/results/YYYY-MM-DD-<commit>.md 에 아래를 담아:

  ## 요약
  - 총점 / 60, 등급 (54+ / 42~53 / 30~41 / <30)
  - 선택 O·근거 X 건수  ← 이게 많으면 점수를 신뢰하면 안 된다
  - 스킬 커밋 해시, 실행 일시

  ## 문항별
  | Q | 선택 | 근거 | 점수 | 응답 요약 |

  ## 규칙별 약점 (eval-set.md §4 채점표 기준)
  | 규칙군 | 해당 문항 | 오답 |
  |---|---|---|
  | C-01 타깃/표본 (불변원리) | Q11,15,19,21,22,28 | ?/6 |
  | C-12 해소 구간 (불변원리) | Q8,25 | ?/2 |
  | C-10 효율화 | Q9,24 | ?/2 |
  | C-11 라벨 부여 | Q2,3 | ?/2 |
  | P-03 표본 층위 | Q23 | ?/1 |
  | P-08 편집 공수 | Q24 | ?/1 |
  | P-10 규격 | Q14 | ?/1 |
  | 연출·진정성 (솔파 §2-8) | Q4,5,6,12 | ?/4 |
  | 카피 구체성 | Q17,20,27 | ?/3 |
  | 교차 판정 | Q28,29,30 | ?/3 |

  ## 판정
  - ⚠️ **C-01에서 2개 이상 틀렸으면 최상위 경고.**
    두 방법론이 완전히 일치한 유일한 영역이라 여기서 틀리면 나머지가 무의미하다.
  - 이전 실행 대비 증감 (results/ 에 이전 파일이 있으면)

## STEP 4 — 분산 확인 (중요)

**1회 실행 결과를 그대로 믿지 마.** LLM 응답은 실행마다 흔들린다.

  - 같은 커밋에서 **3회 실행**하고 평균·최소·최대를 낸다
  - 문항별로 **3회 중 몇 번 맞혔는지**를 기록한다
  - 3회 중 1~2회만 맞은 문항 = **불안정 문항**. 이게 진짜 약점이다
    (3회 다 맞음 = 안다 / 3회 다 틀림 = 모른다 / 1~2회 = 우연에 가깝다)

results 파일에 `안정 정답 / 불안정 / 안정 오답` 3분류를 넣어줘.

## STEP 5 — 베이스라인 커밋

첫 실행 결과를 베이스라인으로 커밋해:

  test(eval): content-gate 스킬 평가 베이스라인 (n회 평균 xx/60)

  - eval/questions.md, eval/answers.md 분리 (INF-04 해소)
  - scripts/run-eval.mjs 평가 러너
  - eval/results/ 베이스라인 3회 실행 결과

그리고 _setup/infra-decisions.md 의 INF-04 상태를
`미착수` → `[완료 YYYY-MM-DD] 커밋 <해시>` 로 바꿔줘. **엔트리는 지우지 마.**

## STEP 6 — 재실행 가이드

eval-set.md §5(확장 방법) 뒤에 "§6. 재실행" 절을 추가해:

  - 언제 돌리나: SKILL.md 수정 / references 갱신 / 규칙 SEED 갱신 후
  - 명령어: `node scripts/run-eval.mjs --runs 3`
  - 판정: 이전 베이스라인 대비 -4점 이상이면 회귀. 수정을 되돌린다
  - ⚠️ 문항이 추가되면 만점이 바뀌므로 **비율(%)로 비교**한다

## 제약

- eval/answers.md 를 스킬 references·프로젝트 지식·프롬프트 어디에도 넣지 마
- 문항을 고치지 마. 정답이 원문 실측에 묶여 있다
- 스킬이 못 푼다고 스킬을 고치지 마 — 이번 작업은 **측정만** 한다.
  수정은 결과를 보고 남헌이 결정한다
- 30문항 중 서술형(Q1, Q6, Q10, Q11, Q13, Q17, Q22, Q23, Q25, Q26, Q27, Q29, Q30)은
  자동 채점이 어렵다. **정답지의 핵심 키워드 매칭 + 애매하면 `수동확인` 마킹**으로
  처리하고, 수동확인 건수를 리포트에 명시해줘
```

## 부록: 남헌이 직접 풀 때와의 차이

| | 프롬프트 B (사람) | **프롬프트 B-CC (스킬)** |
|---|---|---|
| 측정 대상 | 두 방법론의 내면화 | 스킬의 규칙 적용 정확도 |
| 결과 용도 | **D(역방향) 대상 선정** | 스킬 수정 전후 비교 |
| 실행 빈도 | 1회 (또는 분기) | **스킬 수정할 때마다** |
| 정답 노출 위험 | 사람이 안 보면 됨 | **물리 분리 필수** |
| 분산 | 낮음 | **높음 → 3회 실행 필수** |

**둘 다 필요하다.** 스킬 점수가 54/60이어도 남헌이 30/60이면, 게이트를 돌릴 때마다 스킬 판정을 검증 없이 받아들이게 된다. 그러면 스킬이 틀렸을 때 못 잡는다.

**권장 순서**: B-CC(자동, Claude Code) 먼저 → 베이스라인 확보 → 남헌이 B를 나중에 여유 있을 때. 다만 **D(역방향)를 시작하기 전에는 B를 반드시 끝내야 한다.**
