## 1. 리뷰 소스 현황 — 2026-09-21 21:00 KST 실측

### 1-1. 쉬운 말로 — 이 시스템이 뭘 하는 건가

우리 앱은 "셀러가 팔려는 제품을 사람들이 어떻게 말하는지"를 알아야 한다. 그래서 매일 밤 인터넷 여기저기(다나와 리뷰, 유튜브 댓글, 커뮤니티 글…)를 돌면서 새 글을 긁어와 `analysis_inputs` 라는 창고에 쌓는다. 그다음 AI 가 그 글더미에서 "가격이 비싸다", "향이 약냄새 같다" 같은 **불만·바람(속성)** 을 뽑는다.

그림으로 그리면 이렇다:

```
[소스 = 어느 사이트]  →  [타깃 = 그 사이트의 어느 제품·영상·게시판]  →  [매일 밤 수집기]  →  [창고]  →  [AI 속성 추출]
  다나와                    "닥터포헤어 폴리젠 샴푸" 리뷰 페이지              새 리뷰만          2,636건       "가격·향·세정력…"
  유튜브                    영상 2개의 댓글
  82cook 등 4곳             (타깃 0 = 어디를 볼지 정해진 게 없음)             돌긴 도는데 빈손
```

**소스가 "켜져 있다"와 "실제로 가져온다"는 다르다.** 소스는 "이 사이트에 가도 된다"는 허가증이고, 타깃은 "그 사이트의 이 페이지를 봐라"는 주소다. 허가증만 있고 주소가 없으면 수집기는 매일 밤 그 사이트에 가서 아무것도 안 하고 돌아온다. 지금 켜진 소스 6곳 중 4곳이 이 상태다.

## 3. 처방 카드 무관 비율 — 59.5% → 10% 이하로 가는 길

### 3-0. 먼저, 지금 숫자가 뜻하는 것
- 측정: 페인 속성 14건 × 낱말 겹침으로 뽑힌 카드 37장을 LLM(`gemini-3.5-flash-lite`)이 0/1/2 로 채점. **무관(0) 22장 = 59.5%.** 관련 카드 15장, **속성 14건 중 8건만 관련 카드 ≥1장**, 나머지 6건은 카드가 없거나 전부 무관.
- 추이: 82.9%(기준) → 82.5%(카테고리 필터, 효과 0) → 70.4%(운영 원칙 27건 제외) → 59.5%(실패 사례 +2). **내려간 23%p 중 12%p 는 "나쁜 카드를 뺀 것"이고 11%p 가 "좋은 카드를 넣은 것"이다.**
- **"무관 비율"은 정밀도다.** 카드를 아예 안 내면 0% 가 된다. 그래서 목표 10% 는 반드시 **커버리지(관련 카드가 1장 이상인 속성 비율, 지금 57%)** 와 짝으로 잡아야 한다. 아래 비교는 둘을 같이 적는다.

### 3-1. 지금 매칭이 쓰는 것 / 안 쓰는 것 (실측)
쓰는 것: 속성 이름 + 속성 메모 + 프로젝트 시장·한 줄 소개 낱말, `business_model`(물리/SaaS 두 갈래). 끝.
안 쓰는 것: 셀러 프로필의 병목·구매자 유형·가격대·구매 주기, 케이스의 `price_band`·`buyer_type`·`bottleneck`(승인 14건 중 13~14건 채워짐), 실패 사례의 `product_category`(24건 전부 채워짐 — 단 자유 서술이라 24종 전부 다르다).
**그런데 셀러 쪽 값이 비어 있다.** 프로젝트 26건 중 가격대·구매자 유형·병목이 채워진 건 **1건**, 판매자 프로필 0행. 속성을 매칭에 더 쓰려면 먼저 입력이 채워져야 한다 — 코드보다 입력 UX 문제.

### 3-3. A 의 "최소 사례 수" 추정 (지금 추세 기준)
- 실패 사례 +2 건(Care/of·Function of Beauty)이 질의(탈모·건기식)와 직접 겹치는 분야였고, 그것만으로 카드 27→37장(+10: 관련 +7 · 무관 +3), 무관 70.4 → 59.5%(−11%p). **직접 겹치는 사례 1건 ≈ 관련 카드 3~4장 + 무관 1~2장, 무관 비율 −5%p** 가 현재 코퍼스 크기에서의 한계 효과. 탈모 질의가 14건 중 다수라 같은 사례가 여러 속성에 반복 매칭된 덕이 크다 — 다른 도메인 질의가 늘면 사례당 효과는 이보다 작다. 효과는 체감(遞減)한다 — 관련 카드가 늘수록 낱말 겹침이 끌어오는 무관 카드도 같이 는다.
- 질의 유형 8종(효능·가격·세정/체취·사용감·향·자극/성분·용기·제형/보관, `docs/remedy-corpus-expansion-2026-09-21.md` §1-4) × 유형당 선례 2 + 실패 1 + 원칙 1 = **약 32건**을 건기식·헤어케어·뷰티 안에서 채우면 커버리지 80% 이상, 무관 35~45% 로 추정. **낱말 겹침만으로 10% 는 어떤 사례 수에서도 안 나온다** — 코퍼스가 커질수록 우연 겹침(예: "가격"이라는 낱말)이 늘기 때문.
- 지금 편입 가능 후보: `docs/remedy-corpus-expansion-2026-09-21.md` §2 의 잔여 12건(AG1·Ritual·Seed·Dr. Squatch·Liquid Death·뷰티 실패 4·Prose·F8·F9) + draft 3건 승인(Native·락토핏·Hims — 승인되면 즉시 코퍼스에 들어간다, 지금은 미승인이라 매칭에서 제외 중).

### 3-5. 조사 중 떠오른 것
- **실패 사례 `claimed_angle` 을 질의 낱말로 다시 쓰기** (09-21 권고 3 재강조): 24건 중 "가격·향·효능·용기·세정·자극·성분·보관" 같은 페인 유형 낱말이 들어간 건 **4건**(실측, 정규식 대조)이다. 편입 규칙에 "페인 유형 낱말 1개 이상 포함"을 넣으면 A 의 효율이 배로 뛴다. 비용 0.
- **속성 유형 태그 8종을 양쪽에 붙이기**: 질의 속성은 extract 때 LLM 이 이미 이름을 짓는다 — 거기에 유형(효능/가격/…)을 함께 뽑게 하고, 코퍼스에도 같은 유형 태그를 달면 낱말 겹침 대신 **유형 일치**로 1차 필터가 된다. 임베딩 없이 B 보다 효과가 크다. 2~3일.
- **"관련 사례 없음"을 당당히 보여 주기**: 게이트 뒤 빈 속성은 "아직 이 유형의 사례가 없다 — 사례 요청" 버튼으로 바꾸면, 그게 곧 코퍼스 확장 우선순위 큐가 된다(C 의 피드백과 같은 테이블).
