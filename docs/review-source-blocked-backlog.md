# 수집 소스 — 기술 차단으로 보류한 곳 (백로그)

> 남헌 2026-09-30 결정: 아래 소스는 **지금은 진행하지 않는다.** 봇 방어를 User-Agent 위장 등으로 뚫는 것은 하지 않는다.
> 나중에 필요하면 재개할 수 있게, 처음부터 다시 조사하지 않도록 차단 방식과 재개 시 필요한 조치를 한 줄씩 남긴다.
> ⛔ 재개하려면 **남헌이 봇 방어 우회를 명시적으로 다시 승인**해야 한다. 2026-09-30 승인은 "약관·법적 조항"까지였고 이 범위 밖이다.
> 법적 조항 인용은 `ops/state/source-review-queue.md`, 리스크 기록은 `docs/risk-log.md`. 실측일은 모두 2026-09-30, 러너 UA·요청 간격 6.5초·소스당 5요청 이내.

- **Hashnode** — 차단: 글이 있는 `*.hashnode.dev` 호스트의 robots 가 403 + `cf-mitigated: challenge`(Cloudflare 챌린지). `hashnode.com` 의 태그 목록 `/tag/saas` 는 200. 재개 시 필요: 챌린지를 통과하는 브라우저형 접근(방어 우회에 해당) 또는 공식 API 경로 검토 — 단 약관에 "API 수집 금지"가 있어 조항과 충돌한다. 재개 전 재실측 필수(챌린지 정책은 바뀐다).
- **아이보스** — 차단: 게시판 `/ab-6141` 이 403 + `cf-mitigated: challenge`(Cloudflare 챌린지), `/` 는 500 에러 페이지. robots 는 허용(이미지 몇 개만 Disallow). 재개 시 필요: 챌린지 통과(브라우저형 접근, 방어 우회에 해당). 약관에 영리목적 복제 금지 조항.
- **GeekNews** — 차단: `/show`·`/` 모두 CloudFront 가 403 "Forbidden"(챌린지가 아닌 거부 응답). robots 는 허용(`/api/` 등만 Disallow, 학습용 봇 그룹은 `Disallow: /`). 재개 시 필요할 수 있는 조치: UA·요청 헤더 조정 여부에 따라 통과하는지 **미검증** — 러너 UA 로만 시험했다. 조정이 필요하면 방어 우회에 해당하고, 학습용 봇 그룹 Disallow 와 `Content-Signal` 도 재확인해야 한다.
- **Indie Hackers 사용자 글** — 차단이 아니라 기술 접근 불가: 사용자 글 2건이 정적 요청으로 404(편집팀 인터뷰만 200). 페이지 스크립트에 Firebase 흔적이 있어 데이터가 클라이언트 백엔드에서 온다고 추정, 확인은 안 함. 재개 시 필요: 그 백엔드 호출 경로 조사(약관·로그인 벽 재확인). 편집 인터뷰는 별도로 등록 진행 중.
