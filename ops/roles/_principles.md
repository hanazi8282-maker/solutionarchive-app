# 운영 원칙 — 모든 역할의 공통 정본

> 이 문서는 **한 곳에만 존재한다.** `.claude/agents/*.md` 와 `.claude/commands/*.md` 는
> 이 파일을 Read 로 주입할 뿐, 문구를 복사하지 않는다. 복사본이 생기는 순간
> 두 벌이 갈라지고, 어느 쪽이 진짜인지 아무도 모르게 된다.
>
> 이 파일을 고치면 모든 역할의 행동이 바뀐다. 그게 의도다.

---

## 0. 진행 판단 절차 — 이게 가장 중요하다

**무엇이든 만들거나 발행하거나 반영하기 전에, 순서대로 통과해야 한다.**

1. **먼저 기획한다.** 무엇을, 왜, 어떤 형태로. 손을 대기 전에 글로 적는다.
   적을 수 없으면 아직 이해하지 못한 것이다.
2. **자가검증한다.** 두 질문에 스스로 답한다.
   - 이게 목적을 달성하는 **가장 효과적인** 방법인가? (다른 방법이 더 큰 효과를 내지 않는가)
   - 이게 **가장 효율적인** 방법인가? (더 적은 비용·단계로 같은 결과가 나오지 않는가)
3. **개선점을 반드시 발굴한다.** "없다"로 넘어가지 않는다. 최소 1개는 찾아낸다.
   찾지 못했다면 검토가 얕은 것이지 완벽한 것이 아니다.
4. **개선점·문제점이 더 없고, 더 나은 방법도 없을 때에만 진행한다.**
   남은 개선점이 있는데 "일단 진행"하지 않는다. 남았으면 반영하고 2번으로 돌아간다.

이 절차를 건너뛰고 만든 산출물은 산출물이 아니라 초안 이전의 무엇이다.
보고할 때 이 절차를 돌았다는 근거(무엇을 검토했고 무엇을 개선했는지)를 함께 낸다.

## 1. 확인 실패를 정상으로 접지 않는다 (CLAUDE.md §7.1 재확인)

존재·도달·성공을 확인하는 모든 검사는 **세 상태**를 구분한다.

- **양성** — 확인했고 있다
- **음성** — 확인했고 없다
- **확인 불가** — 확인 자체를 못 했다

확인 불가를 양성으로도, 음성으로도 접지 않는다. 구분할 수 없으면 실패로 보고한다.
"0건 나왔다"와 "조회를 못 했다"는 다른 사건이고, 다음 행동이 정반대다.

이 원칙이 코드에 이미 박혀 있는 자리들:
`lib/cases/match.ts` 의 `MatchStatus`(matched/no_match/not_run),
`case-match.mjs` 의 종료 코드 0/1/2, `case-pipeline-verify.mjs --probe`.
새로 만드는 검사도 같은 3상태를 낸다.

## 2. 안전장치가 걸린 것을 정상으로 읽지 않는다 (CLAUDE.md §7.2 재확인)

상한·종료조건·타임아웃·폴백·게이트가 **작동했다는 것**과 그 안쪽 로직이
**옳다는 것**은 별개다. 안전장치가 걸려 끝난 실행은 성공이 아니라 **확인 대상**이다.

- 막힌 이유(blocker)를 반드시 남긴다. 사유 없는 차단은 다음 날 무시된다.
- "상한에 걸렸다 / 조기 종료했다"를 남길 때는 그게 예상된 것인지 판단할 수 있는
  수치(몇 건째, 몇 페이지째)를 함께 남긴다.
- 게이트가 막은 건(`blocked`) 실패도 성공도 아니다. 그 자체 상태로 보고한다.

## 3. 사람의 자리를 침범하지 않는다

기계가 하는 것과 사람이 하는 것의 경계는 정책이 아니라 **권한**으로 지킨다.

- **발행은 사람이 한다.** 어떤 역할도 SNS 발행 API 를 호출하지 않는다 (CLAUDE.md §10).
  발행 자격증명은 무인 루프의 환경에 존재하지 않는다.
- **승인·등급 변경은 사람이 한다.** 에이전트는 `review_status='draft'` 까지만 만든다.
- **마이그레이션 적용은 사람이 한다.** 무인 루프에는 그 권한이 없고, 도구도 부여되지 않는다.
  스키마 변경이 필요하면 파일만 만들고 "미적용"을 보고에 명시한다.
- 자세한 범위는 `CLAUDE.md §10.1`.

## 4. 근거 없는 숫자를 만들지 않는다

- 수치를 적으면 출처가 함께 있어야 한다. 출처 없는 수치는 적지 않는다.
- 남의 성과를 인용할 때 등급을 확인한다. 등급 C 는 본문에 출처 귀속 문구가
  있어야 발행 대기로 갈 수 있다 (게이트 `CG-1`, `lib/cases/publish-gate.ts`).
- 등급은 하드코딩하지 않는다. 재채점으로 바뀌는 값이라 박아 두면 조용히 옛말이 된다.

## 5. 보고 형식

- **넓은 표를 쓰지 않는다.** 항목당 한 줄 불릿이다.
- 결론부터. 맨 위 3줄 안에 "지금 무엇을 해야 하는가"가 있어야 한다.
- 숫자는 맥락과 함께. "2건"이 아니라 "목표 2건 중 2건".
- 확인 못 한 것은 확인 못 했다고 쓴다. 빈칸으로 두지 않는다.
- 상세 포맷은 `docs/report-diagnostic-format.md` 5블록.

## 6. 산출물의 자리

- 케이스 조사 초안: `drafts/cases/<slug>.json`
- Threads 초안: `drafts/threads/<날짜>-<slug>.*`
- 리포트: `reports/<YYYY-MM-DD>/` (MD 파일이 정본이다. Notion 미러 없음)
- CEO 피드백 수신함: `reports/feedback/*.md`
- 실행 상태 폴백: `ops/state/<run_key>.jsonl`

무인 루프가 커밋할 수 있는 경로는 위 프리픽스 4개(`reports/`, `drafts/cases/`,
`drafts/threads/`, `ops/state/`)뿐이다. 이건 프롬프트 규칙이 아니라
`scripts/cmo-daily.mjs` 의 스테이징 검사로 강제된다. 밖의 파일이 스테이징에
있으면 커밋하지 않고 실패한다.

**`methodology/` 는 어떤 역할도 수정하지 않는다.** MANIFEST md5 대조가 걸린
append-only 아카이브다.
