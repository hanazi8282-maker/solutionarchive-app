# 한도 대장 — 일 예산 $15·월 경보선 정리안 (v71as, 2026-10-19)

라벨: [직접 실행 확인] = 오늘 DB·변수 읽기 · [코드만 확인] = 코드 읽기 · [추정] = 계산식 명시. **이 문서는 제안이다 — 변수는 바꾸지 않았다**(오케스트레이터가 적용).

## 1. 먼저 알아야 할 사실 3개
1. **$ 한도는 "하루 합계"가 아니라 "한 프로세스(한 실행)의 하루 누적"이다** [코드만 확인: `lib/analysis/budget.ts` `daily` 는 프로세스 메모리, UTC 날짜가 바뀌면 리셋]. 실행이 여러 번 돌면 한도는 실행마다 새로 시작한다. 교차 실행 지출 장부는 DB 에 없다.
2. **과금되는 경로는 2차 판정(Gemini)과 번역뿐이다.** 1차 판정(claude-cli, `claude-sonnet-5-5`)은 구독 경로라 예산 밖이다(`llm.ts` UNMETERED) [코드만 확인]. 24h 판정 행: 1차 6,946건(무과금) · 2차 Gemini 7,158건(과금) [직접 실행 확인: `review_relevance_verdicts`].
3. **"월 경보선 $250"에 해당하는 코드·변수가 리포에 없다.** $250 은 폐기된 "Agent SDK 크레딧"(2026-09-26 정정, claude-cli 와 무관)에서 온 숫자다 [코드만 확인: budget.ts 주석]. 즉 정리할 "월 상한 코드"는 없고, 새로 정하는 일이다.

## 2. 일일 사용 추정 (이 PR 의 `limit-rollback-eval.mjs` 가 하루 4번 찍는 줄)
- 2차 판정 Gemini 24h 7,158건 × 보수 단가(budget.ts `usdFor(1200자, 150토큰)` = $0.0009) ≈ **$6.4/일** [추정]. 단가는 budget.ts 기본값(입력 $0.5/Mtok, 출력 $4/Mtok)이 실제 Gemini flash-lite 단가보다 높은 보수 추정이라 실제는 이보다 낮을 가능성이 크다 — 청구서로 보정 필요 [확인 불가].
- 수집 ×3(원수집 ≈ 9,400/일)이면 2차 판정도 ≈ 3배 → 추정 ≈ **$19/일** > $15. HN 사전 필터(비용 절감, v71as 병행)가 필수인 이유다.

## 3. 한도 대장 항목 (제안: 이전값 → 새값 / 롤백 / 24h 재평가)
| 이름 | 이전 → 새 | 롤백 | 24h 재평가 기준 |
|---|---|---|---|
| `LLM_DAILY_BUDGET_USD` (리포 변수, 현재 10) | 10 → **15** | `gh variable set LLM_DAILY_BUDGET_USD --body 10` | 추정 사용액 줄(`[한도 재평가]`)이 한도의 80% 미만이거나 상한 초과(`LlmBudgetExceededError`) 로그가 없어야 유지 |
| `nightly-relevance.yml` 폴백 `'5'` | 변수 미설정 때만 쓰임 | 변경 없음 | 변수가 있으면 무관 — 건드리지 않는다 |
| `TRANSLATE_DAILY_BUDGET_USD` (번역, 현재 3) | 유지 | — | 다국어 ③ 시작 시 별도 산정 |
| 월 경보선 (신규) | 없음 → **$340** (= $15×30 의 75%) | 값 삭제 | 월 누적 추정 > 경보선이면 Notion 일일 로그에 경고 |
| 월 상한 (신규) | 없음 → **$450** (= $15×30, 이론 천장) | 값 삭제 | — |

- 경보선 선택지: (A) $250 유지 = 월 이론 천장의 56%, 일 $15 를 매일 다 쓰면 17일째에 울림. (B) $340 = 75%(추천) — 평소 사용(필요한 만큼만, $15 를 채우지 않는다)에는 조용하고 천장 근처에서만 울린다. 숫자는 오케스트레이터 재량([CLAUDE.md] 문구 변경 아님).
- 월 누적은 지출 장부가 없으므로 **일 추정 합계**로 센다(이 PR 은 일 추정 줄만 낸다). 정확한 월 경보에는 `llm_spend_log` 같은 장부(하루 1행: 날짜·프로바이더·호출 수·추정액)가 필요하다 — 마이그 초안은 이 PR 범위 밖(필요하면 별도 PR). [확인 불가: 실제 청구액]

## 4. §10.1 대조 — 구현하지 않은 것·충돌 목록 (CLAUDE.md 직접 수정 금지)
- 한도 **자동 상향**: `daily_request_cap` 만 `review-request-cap.mjs` 가 2배 이내로 자동 반영한다. 램프 `cap_base` 올리기는 "사람", 리포 변수(WINDOW_MAX_REQUESTS 등)를 워크플로가 바꾸는 권한은 없다. → 이 PR 의 평가기는 **상향 가능 소스를 "제안"만** 한다. "자율 범위 안 한 단계 상향 자동 시행"을 워크플로로 하려면 §10.1 에 `review_source_ramp.cap_base` 올리기·변수 쓰기 권한 문구가 새로 필요 → **충돌 목록**.
- 한도 **자동 롤백**: "상한을 내리는 변경은 자동으로 하지 않는다"(§10.1 요청 상한 줄). 램프 `pct_step` 안전 되돌리기만 허용된다. → 평가기는 롤백 **판정과 안내(SQL/인용)만** 파일로 남기고 적용하지 않는다. cap/변수 자동 롤백은 문구 변경 필요 → **충돌 목록**.
- 하루 4회 워크플로가 커밋하는 곳은 `reports/` 뿐이다(허용 프리픽스 검사 포함). 새 secret·permissions 확대 없음.
