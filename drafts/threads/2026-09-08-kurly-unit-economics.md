## 0. 원 지시와 다르게 처리한 것 두 가지 (오케스트레이터 확인 필요)

### 0-1. `content_code` 를 `CS-20260908-02` 로 바꿨다

원 지시는 `CS-20260908-01` 이었다. 그런데 같은 코드를 오늘 이미
`drafts/threads/2026-09-08-elf-beauty-awareness-engine.stage.json` 이 쓰고 있다.

`scripts/case-draft-stage.mjs` 는
- `content_items` 를 `upsert(..., { onConflict: 'code' })` 로 넣고 (L167)
- `posts` 를 `.eq('content_code', ...).maybeSingle()` 로 단건 조회한다 (L215)

즉 같은 코드로 스테이징하면 **elf 건을 조용히 덮어쓴다.** 실패하지 않고 덮어쓰기
때문에 사람이 알아채기 어렵다. 2026-09-07 배치에서 카바나 ↔ 캐스퍼 사이에 같은
사고가 있었고 `CS-20260907-02` 로 채번을 바꾼 전례가 있다. 같은 처리를 했다.

`LOG` 코드도 같은 이유로 `LOG-20260908-02` 다 (`-01` 은 elf 건이 씀).

### 0-2. 등급 "A" 를 그대로 쓰지 않았다 — ~~확인 불가~~ → **2026-09-11 확인됨: A**

> ✅ **[2026-09-11 해소] 등급은 `A` 다. 확인 불가가 아니다.**
>
> `case_moves 089c1ba8-b929-445a-a64b-21e703aecdf6` 의 `evidence_grade` 를
> 대상 프로젝트(`qmgrfqjfxqhxuufrnkwf`)에 직접 조회해 **`A`** 를 확인했다.
> 조회 경로는 `.env.local` 의 service_role 이다 — Supabase MCP 는 다른 프로젝트
> (`hrplbrstntyanzwxcsft`)를 가리키고 있어 쓰지 않았다.
>
> 아래 §0-2 본문의 "확인 불가"는 **작성 시점(2026-09-08)의 상태**이고, 그때는
> 옳은 판정이었다 — 작가 역할에는 DB 도구가 없다(`tools: Read, Grep, Glob, Write`).
> 기록을 고쳐 쓰지 않고 결과만 위에 얹는다.
>
> **지금 시점의 판정:**
> - 등급 A → **CG-1 비대상.** 출처 귀속 문구는 의무가 아니다.
> - 그래도 본문의 "회사가 밝힌 감사 전 잠정치" 문구는 **그대로 둔다.** 잠정치를
>   잠정치라고 밝히는 정직한 문장이라 등급과 무관하게 남길 이유가 있다.
> - 산식 재계산이 C 로 나온 것(아래)은 **초안 JSON 의 근거만 대입한 결과**다.
>   DB 쪽에 근거가 더 있거나 재채점이 돌았다는 뜻이고, 정본은 DB 값 A 다.

이건 단순 이관 문제가 아니라 **판정을 바꾼 지점**이라 따로 적는다.

- **지시값**: 등급 A
- **내가 확인할 수 있었던 것**: 이 역할의 도구는 Read/Grep/Glob/Write 뿐이라
  `case_moves.evidence_grade` 를 DB 에서 직접 조회할 수 없다 → **확인 불가**
- **대신 한 것**: 조사 초안 `drafts/cases/kurly-unit-economics.json` 의 근거 행을
  `lib/cases/draft.ts` 의 `gradeMove()` 산식에 손으로 대입했다.

무브 0(이 글이 딛고 선 무브)의 근거 2건:

| 근거 | tier | self_reported | estimate | regulatory_filing |
|---|---|---|---|---|
| 연합뉴스 실적 기사 | secondary | true | true | false |
| DART 검색(원문 열지 못함) | tertiary | true | false | false |

산식을 순서대로 따라가면:

1. `attested`(법정 공시 ∧ ¬추정 ∧ ¬발행사정의) → **0건**. A 아님
2. `nonSelfPrimary`(1차 ∧ ¬자기보고 ∧ ¬추정) → **0건**. A 아님
3. `corroborating`(¬자기보고 ∧ ¬추정 ∧ 1·2차) → **0건** → `folded.keys.size = 0`. A 아님
4. `selfPrimary`(1차 ∧ 자기보고) → **0건** (secondary·tertiary 뿐). B 경로 없음
5. `estimates > 0` ∧ `folded.keys.size === 0` → **`grade: 'C'`,
   reason: "추정치뿐 (1건) — 실측 출처 없음"**

**즉 조사 초안 그대로라면 이 무브는 C 다.** 조사 초안 자신도 그렇게 설계했다고
적어 놨다 — DART 행의 `supports_claim` 에 *"원문을 못 봤으므로
is_regulatory_filing 을 false 로 둔다 — true 로 두면 등급 산식이 이 행 하나로
A 를 줘 버린다"* 라고 명시돼 있다.

**그래서 어떻게 했나.**

DB 의 실제 값이 A 일 가능성도 남아 있다(초안 이후 근거가 추가됐거나 재채점됐을 수
있다). 나는 그것을 **확인하지 못했다.** 확인 불가를 A 로도 C 로도 접지 않는다
(CLAUDE.md §7.1, `_principles.md` §1). 대신 **두 경우 모두에서 안전한 쪽**을
택했다 — 등급이 C 일 때 필요한 **CG-1 출처 귀속 문구를 본문에 선제적으로 넣었다.**

- 등급이 실제 A 라면: 귀속 문구는 CG-1 대상이 아니지만 있어도 해가 없다
  (오히려 잠정치임을 밝히는 정직한 문장이다)
- 등급이 실제 C 라면: 이 문구가 없으면 `case-draft-stage.mjs` 가 **exit 4 로
  차단**한다. 있어서 통과한다

본문·메모 어디에도 **등급 문자를 하드코딩하지 않았다.** 스테이징 스크립트가
`case_moves` 에서 직접 읽어 `notes` 에 박는다(L180~195). 그게 정본이다.

> ⛔ 사람이 승인 전에 반드시 할 것: DART 에서 컬리 감사보고서 원문을 열어
> 183억 / 2,334억 을 대조하고, `case_moves` 의 `evidence_grade` 실제값을 확인한다.

## 5. 지문

> **"성장률이 꺾인 게 사고가 아니라 결정이었다."**

**왜 이게 가장 뾰족한가.** 성장률 하락은 거의 모든 조직에서 **변명해야 하는 숫자**다.
이 문장은 그 숫자를 **설명해야 하는 선택**의 자리로 옮긴다. 그리고 그 이동이
수사가 아니라는 걸 바로 앞 두 숫자가 증명한다 — 같은 기간에 매출 증가율(+6%)이
내려가고 영업손실(2,334억 → 183억)도 같이 내려갔다. 보통 성장률이 꺾이면 손실이
따라 줄지 않는데, 여기서는 줄었다. 그게 이 사례의 각이다.

**이 문장이 없으면** 글은 "컬리가 적자를 줄였대"라는 뉴스 요약으로 평평해진다.
U-2 의 "잘라내서 단독으로 성립하는 조각" 기준에 걸리는 유일한 문장이기도 하다.

## 8. 진행 판단 절차 기록 (`_principles.md` §0)

- **기획**: 무브 1개(OPERATIONS · 성장률↓ / 손실↓)만 옮긴다. 같은 케이스의 두 번째
  무브(조정 EBITDA)는 **쓰지 않았다** — 한 글에 두 무브를 넣지 않는다는 규칙이자,
  "EBITDA 흑자"와 "영업이익 적자"를 같은 글에 넣으면 U-2 의 뾰족한 지점이 둘로 갈라진다.
  (다만 "흑자가 아니다"라는 **방향 단서**는 무브 0 자신의 수치가 여전히 음수라는
  사실에서 나오므로 본문에 남겼다. 무브 1의 숫자는 인용하지 않았다.)
- **자가검증 ①(효과)**: 대안 각으로 "매출 +6% vs 거래액 +12%" 를 검토했으나
  업계 내부 언어라 U-1(관심 없는 사람도 볼 이유)에서 약하다. 폐기.
- **자가검증 ②(효율)**: 텍스트 약 310자 + 자기답글. 더 적은 단계로 같은 결과가
  나오는 방법은 없다.
- **개선점(발굴한 것 3개, 전부 반영)**:
  1. 첫 카피를 "성장률을 일부러 떨어뜨렸다"(15자)로 줄여 **G-4 15자 예외를 쓰지
     않게 했다.** 직전 배치 3건이 연속으로 예외를 승계하고 있었고, 예외가 세 번
     반복되면 그건 예외가 아니라 규칙 위반이다.
  2. "92% 감소" 같은 파생 계산을 넣으려다 뺐다. 근거에 없는 수치를 만들지 않는다.
  3. `content_code`·`LOG` 코드 충돌을 스테이징 전에 발견해 `-02` 로 채번했다.
     발견 못 했으면 elf 건이 조용히 덮여 썼다.
- **작업 중 낸 실수 1건(보고함)**: `drafts/threads/2026-09-08-kurly-unit-economics.tmp`
