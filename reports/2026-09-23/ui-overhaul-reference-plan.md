# UI 대대적 개편 — 레퍼런스에서 가져올 것 (트랙 1~3 체크포인트, 2026-09-23)

> 남헌 확정 위임(2026-09-23): 트랙 1 전체 디자인(Foreplay·Trend Seeker) · 트랙 2 상세 페이지 구조(Trend Seeker·BigIdeasDB·PainMap·Preuve) + Atria 썸네일·하단 구조 · 트랙 3 카드 그리드(EO Planet). **코드 착수 전 체크포인트** — 이 문서로 남헌 확인을 받은 뒤 구현한다.
> 조사 방법: 남헌이 열어 둔 크롬으로 8개 사이트를 직접 열어 화면·computed style(폰트·배경·radius)·페이지 구조를 실측. 로그인 벽 뒤 앱 화면은 **확인 불가**로 적었다. Trend Seeker 상세·Preuve 리포트는 차트 렌더러 타임아웃으로 스크린샷 대신 DOM 텍스트 구조로 확보.

## TL;DR (3줄)

1. **디자인 톤은 "라이트 앱 + 다크 랜딩" 하이브리드를 권고한다.** 앱 내부(그리드·상세·검색)는 Trend Seeker 감각(슬레이트 텍스트 `#0F172A`, 옅은 회청 배경 `#F4F7FA`, 흰 카드 radius 16, 증거 배지), 랜딩·CTA 배너는 Foreplay 감각(딥네이비 `#020308`, 큰 디스플레이 서체, 흰 섹션 카드 radius 32). 한국어 본문이 길어 다크 전면은 가독성 손해.
2. **상세 페이지는 "판정 → 근거 → 옮기기 → 다음 케이스" 순서 11블록.** 히어로(로고 썸네일+등급 2축+Verified) → 왜 이 등급인가(점수 분해) → 수치 타일(before→after) → 문제/무브/왜 됐나/전제/내일 할 행동 → 근거 목록(출처 등급별) → 갈린 사례·실패 경고 → VOC 인용 → 피드백 위젯 → **관련 케이스 3 + CTA 배너(Atria, 확정)**. 사이드 TOC 고정.
3. **일정 충돌을 먼저 확인해야 한다.** 트랙 1~3 합계 **≈38~46h**(디자인 토큰 10~14 · 상세 라우트 신설 12~16 · 공개 그리드 8~10 · 로고 파이프라인 4~6 · QA 4)이고, 9/30 잔여(칼럼 링크·사전검증 배지·HN 타임아웃)와 겹친다. 9/30 안에 다 넣으려면 **상세 페이지(트랙 2)를 먼저, 전면 리스타일(트랙 1)은 10/4까지**로 나누는 것을 권고한다.

## 1. 결정 필요 — 남헌만 답할 수 있는 것 (5건)

**Q1. 기본 톤: 라이트 앱 + 다크 랜딩(권고) / 전면 다크(Foreplay·EO Planet) / 전면 라이트(Trend Seeker·Preuve).**
- 권고 이유: 케이스 본문·근거 인용은 한국어 장문이라 라이트가 읽기 쉽고, 4곳 중 3곳(Trend Seeker·Preuve·BigIdeasDB)이 앱은 라이트다. 다크는 랜딩 히어로·하단 CTA 배너에서만 써서 Foreplay의 "제품감"을 가져온다. 대가: 두 팔레트를 토큰으로 유지해야 한다(지금 `app/_ds` 토큰 CSS 5종에 이미 라이트/다크 자리가 있어 비용은 작다).

**Q2. 서체: 한글 Pretendard 셀프호스팅(권고) / Noto Sans KR(Google Fonts) / 시스템 폰트.**
- 레퍼런스 실측: Foreplay·Trend Seeker·BigIdeasDB·Atria 본문 전부 Inter, 디스플레이는 Inter Display(상용)·ABC Favorit(상용)·Instrument Serif(IdeaBrowser). EO Planet은 Apple SD Gothic/Noto Sans KR.
- 권고 Pretendard: 한국 스타트업 사이트 표준이고 Inter와 골격이 같아 영문 혼용이 자연스럽다. 대가: 폰트 파일(서브셋 ~300KB) 리포 동봉·CSP 확인. Noto Sans KR은 Google Fonts라 CSP 허용이 확실하지만 자간이 넓어 "제품감"이 떨어진다.

**Q3. 상세 라우트 신설 `/cases/[slug]` — 지금 없다.** 이번 개편의 전제다. 카드 썸네일·관련 케이스 3·CTA 배너 전부 이 라우트 위에 올라간다. 승인해 주면 트랙 2에서 만든다(≈12~16h).

**Q4. 브랜드 로고 소스: 외부 로고 API(예: `logo.clearbit.com/<domain>`, 무료·비인증) / 사람이 업로드 / 둘 다.**
- Atria 방식(썸네일 = 듀오톤 배경 + 흰 로고 중앙)을 그대로 쓰려면 케이스마다 로고가 필요하다(현재 승인 22건). 외부 API는 코드 0줄에 가깝지만 상표 이용 리스크·API 종속이 있고, 업로드는 남헌 손이 든다. 권고: **외부 API 기본 + 없거나 틀리면 업로드로 덮어쓰기**(`case_studies.logo_url` 컬럼 1개 추가, 비파괴).

**Q5. 9/30 우선순위.** 트랙 1~3 ≈40h는 9/30 잔여와 합치면 8일 안에 안 들어간다. A(권고) 트랙 2 상세 + 트랙 3 그리드를 9/30, 트랙 1 전면 리스타일은 10/4 / B 전부 9/30(칼럼 링크·사전검증 배지 후순위) / C 개편 전체를 10/4로.

## 2. 트랙 1 — 전체 디자인: 가져올 것 / 안 가져올 것

**Foreplay(실측: bg `rgb(2,3,8)`, 본문 Inter 16px, 뮤트 텍스트 흰색 36%, H1 Inter Display 60/68px 600 자간 −0.45px, radius 6·10·12·18·24·32·36·100px)**
- 가져올 것: ① 딥네이비 바탕에 **흰 대형 섹션 카드(radius 32~36)** 를 띄우는 리듬 — 랜딩·CTA 배너에 ② 눈썹 라벨(대문자·자간 넓힘, 예 "RESEARCH & INSPIRATION") — 섹션 헤더 규칙 ③ 로고 월("POWERING +10,000 …") — 우리는 "승인 케이스 N건 · 근거 N행"으로 치환 ④ 흰 알약 CTA + 화살표.
- 안 가져올 것: 전면 다크(Q1), 제품 스크린샷 콜라주(우리는 케이스가 콘텐츠), 챗 위젯.

**Trend Seeker(실측: bg `#F4F7FA`, 텍스트 `#0F172A`, Inter/SF Pro, H1 44px 800, 액센트 코랄 버튼, 초록 통계 알약 "+2.1k ideas this week")**
- 가져올 것: ① 슬레이트 텍스트 + 회청 배경 + 흰 카드 radius 16 — **앱 기본 팔레트** ② 카드 좌상단 **증거 배지**("22 Signals +4", "NEW", "Pro") — 우리는 "근거 5 · 무브 2 · 등급 A/C" ③ 상단 한 줄 통계 알약(+N this week) — "이번 주 케이스 +N · 리뷰 +N" ④ 헤더 중앙 검색창 ⑤ 카테고리 칩 행(SaaS·AI·Developer Tools…) — 우리 `reader_problem` 7칩.
- 안 가져올 것: Google Trends 차트(우리 데이터 없음), 코랄 액센트(브랜드 보라 유지).

**공통 토큰 제안(초안, `app/_ds` 토큰 파일 갱신)**
- 라이트: `--bg #F4F7FA` · `--surface #FFFFFF` · `--ink #0F172A` · `--muted #5B6874` · `--line #E2E8F0` · `--brand` 기존 보라 유지 · radius 카드 16 / 배너 32 / 알약 100.
- 다크(랜딩·배너): `--bg #020308` · `--surface #FFFFFF`(섹션 카드) · `--ink #FFFFFF` · `--muted rgba(255,255,255,.55)`(36%는 한글에 너무 흐림).
- 타이포: 디스플레이 Pretendard 700 44/60px 자간 −0.02em, 본문 16px/1.7, 눈썹 12px 대문자 자간 .08em, 숫자는 `tabular-nums`.

## 3. 트랙 2 — 케이스 상세 페이지 구조 (11블록)

레퍼런스 4곳의 구조를 실측해 겹치는 것만 남겼다. 괄호는 어디서 가져왔는지.

1. **히어로** — 브랜드 로고 썸네일(Atria: 듀오톤 배경+흰 로고) · 제목은 "문제 → 수" 형태(IdeaBrowser 제목 방식) · 한 줄 요약 · 메타 칩(병목·레버·독자 문제 유형·기간·outcome_status) · **등급 배지 2축**(인사이트/사실확인, 이미 있음) · "근거 N건 · 사람 검토 완료" 배지(Preuve "Verified", Trend Seeker "High confidence · 100% coverage") · 액션: 저장·공유·"내 상황으로 옮기기"(Trend Seeker Like/Save/Share).
2. **왜 이 등급인가** — Trend Seeker "Score contribution: 항목별 points earned / available" 를 우리 등급 산식으로 치환: transfer_note 유무 · preconditions 유무 · 근거 수 · 자기보고 비율 · 공시 여부 → 각 항목 통과/미달 + "산식 보기" 링크(`docs/evidence-rules.md`). **숫자 점수는 만들지 않는다**(등급 4단계 그대로, SP-004 차별화 유지).
3. **수치 타일** — Atria "Estimated Results" 박스: 무브별 `metric_name before → after (unit)` 3~5칸, 추정이면 "추정" 배지(기존 규칙).
4. **문제 / 무브(무엇을 했나) / 왜 됐나·안 됐나 / 전제(preconditions) / 내일 할 행동(transfer_note)** — IdeaBrowser Problem·Solution·Why Now + Preuve "The Bottom Line"·"Watch out for" 를 우리 5필드에 1:1 대응. 무브가 여럿이면 무브마다 반복.
5. **근거 목록** — Preuve Evidence 탭 방식: 출처를 그룹(공시 / 1차 자기보고 / 2차 보도 / 추정)으로 묶고 도메인·날짜·인용 300자 · 그룹별 건수 표시("77 sources backing this analysis" → "근거 5건 · 공시 2 · 자기보고 3").
6. **갈린 사례 + 실패 경고** — 같은 병목·레버의 반대 방향 케이스(`pairMoves`, 이미 있음) + `failed_angles` 빨강 카드(이미 있음). SaaS 짝이 0이면 정직한 빈 상태(기존 문구).
7. **VOC 인용** — Trend Seeker Signals 탭: 이 케이스 병목과 같은 `reader_problem` 의 HN 댓글 3~5건(T2 relevant 판정분). 없으면 섹션 숨김.
8. **피드백 위젯** — IdeaBrowser "What'd you think of this idea?": 👍/👎 + 한 줄. **저장처는 `saved_examples` 가 아니라 새 테이블**(리뷰 관련성 채점과 같은 모양) — T3 사람 신호로 쓴다.
9. **관련 케이스 3장** — Atria "Related case studies": 같은 `reader_problem` 우선 → 같은 병목 → 같은 종류(SaaS). 카드는 트랙 3과 동일 컴포넌트.
10. **CTA 배너** — Atria 하단 그라데이션 배너: "내 문제로 검색하기" → `/cases/search`(문제 유형 프리필) + 로그인 전이면 "베타 신청".
11. **사이드 TOC**(데스크톱 sticky, Atria) — 모바일은 상단 칩으로 접힘. Preuve 식 좌측 섹션 네비는 리포트가 15섹션이라 필요했던 것, 우리는 11블록 한 페이지 스크롤이 맞다.

**안 가져올 것과 이유**: Preuve 숫자 점수 링(0~100) — 우리는 등급이 차별화(SP-004)이고 숫자 점수는 "근거 없는 숫자"가 된다 · IdeaBrowser 프레임워크 매트릭스(Value Equation·ACP) — 데이터 없음 · Trend Seeker Google Trends 차트 — 데이터 없음 · PainMap — 공개 상세 페이지가 없어 구조 참고 불가(마케팅 페이지뿐, 앱은 로그인 벽).

**신설·변경**: 라우트 `app/cases/[slug]/page.tsx`(Q3) · `case_studies.logo_url text NULL`(Q4, 비파괴) · 피드백 테이블 1개(비파괴) · 검색 카드 링크를 목록 앵커에서 상세로 교체 · 칼럼 읽기 화면의 케이스 링크도 상세로.

## 4. 트랙 3 — 카드 그리드 (EO Planet 구조 + Atria 썸네일)

**EO Planet 실측(bg `#1C1C20`, Noto Sans KR/Apple SD Gothic, 초록 액센트)**: 좌측 카테고리 사이드바(13개, 선택 항목 강조, "마케팅 4494" 건수) · 카드 = 태그 칩(# 마케팅 # 트렌드) + 제목 + 2줄 발췌 + 작성자 줄(아바타·이름·소속|직함·N시간 전) + 우측 썸네일 · 정렬 드롭다운(최신순) · 검색창 · 목록 사이 광고 배너 · 우하단 FAB(아티클 작성하기) · 기사 상세 우측에 작성자 카드+"이 사람의 다른 아티클" · 하단 "추천 아티클" 3.

**가져올 것**
- 좌측 사이드바 = `reader_problem` 7유형 + 종류(SaaS 기본·소비재 포함·전체) + 건수. 모바일은 상단 가로 스크롤 칩.
- 카드 구조 = 문제 유형 칩 + 병목 칩 · 제목("문제 → 수") · 한 줄 = `transfer_note` 앞 60자(EO의 발췌 자리에 **독자가 가져갈 행동**을 둔다) · 메타 줄 = 브랜드명 · 등급 배지 2축 · 무브 N · 승인일 · 우측 썸네일 = Atria 듀오톤 로고.
- 정렬: 최신 승인순(기본) / 등급순 / 무브 많은 순. 검색창은 `/cases/search` 로 연결.
- 상세 하단 "추천 3" — 트랙 2의 9번과 같은 컴포넌트.
- 안 가져올 것: 광고 배너 자리, FAB(사용자가 글을 쓰는 사이트가 아님), 다크 기본(Q1).

**Atria 썸네일 실측**: 3열 그리드, 썸네일 = 제품 사진 콜라주에 컬러 오버레이(듀오톤) + 흰 로고 중앙, 위에 "CASE STUDY" 핑크 라벨 + 날짜, 제목, 2줄 요약. 우리는 사진이 없으니 **컬러 오버레이만 (병목별 색) + 로고**로 단순화.

**라우트**: 공개 그리드를 어디에 두나 — 현재 `/cases` 는 검수 화면(로그인 벽)이다. 권고: `/cases` 를 공개 그리드로 바꾸고 검수는 `/cases/review` 로 옮긴다(auth-selftest 음성 케이스 추가 필요, §10.2 인증 경계 → 남헌 승인 1건 더). 대안: `/library` 신설.

## 5. 소요 추정과 순서

- 로고 파이프라인(외부 API 폴백 + 업로드 + 승인 22건 채우기): **4~6h + 남헌 확인**.
- QA(auth-selftest·빌드·모바일 375px 11라우트): **4h**.
- **합계 38~50h.** 순서: 트랙 2 → 3 → 1(토큰은 2·3 컴포넌트 만들 때 같이 잡되, 전 화면 적용은 마지막).

## 6. 확인 불가로 남긴 것
- Trend Seeker·Preuve·IdeaBrowser·BigIdeasDB·PainMap의 **로그인 뒤 앱 화면**(대시보드·저장함·필터 UI) — 가입 없이 못 본다.
- Trend Seeker 상세·Preuve 리포트의 스크린샷(렌더러 타임아웃) — DOM 텍스트 구조로 대체.
- 각 사이트 모바일 레이아웃 — 데스크톱 뷰포트만 봤다.
