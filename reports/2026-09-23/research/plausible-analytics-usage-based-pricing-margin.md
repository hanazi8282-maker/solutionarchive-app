# 조사 노트 — Plausible Analytics (plausible-analytics-usage-based-pricing-margin)

- 조사일: 2026-09-23 / 조사원: sa-cmo-researcher
- 큐 사유: coverage_gap (UNIT_ECONOMICS 승인 케이스 1곳뿐 — 매칭 성립에 3곳 필요) / 목표 병목: UNIT_ECONOMICS
- 시장: SaaS · 1인/소규모 팀 소프트웨어 → **충족**. 창업자 1인(Uku Täht)이 시작, 2020년 3월부터
  공동창업자 Marko Saric 합류해 2인, ARR 100만 달러 시점(2022-06)까지도 4인.
- 대상: "미정"이었음. WebSearch 로 직접 정함(아래 §1).
- 결과: `outcome_status=active`, 무브 2건 모두 `outcome_direction=positive`. 기존 적립분
  (`cydoc-cost-plus-pricing-collapse`, 실패 사례)과 짝을 이루는 **성공 사례**.

## 1. 왜 이 대상인가

큐가 이미 적립된 UNIT_ECONOMICS 케이스는 Cydoc(실패) 1건뿐이라고 명시했다. 매칭 성립에
3곳이 필요하다고 했으므로, 실패 사례와 대비되는 **긍정 사례**를 찾는 데 집중했다. 제외 슬러그
목록에 SaaS 유닛 이코노믹스 성공 사례가 없어서(`kurly-unit-economics`·`casper-dtc-unit-economics`·
`blueland-water-weight-unit-economics`·`shyp-flat-fee-unit-economics-collapse` 는 전부 소비재
또는 실패 사례), 다음 기준으로 후보를 좁혔다: (1) SaaS·소프트웨어, (2) 1인 또는 소규모 팀,
(3) 창업자 1인칭 출처가 있는, (4) 원가 구조·가격 결정이 명시적으로 서술된 사례.

후보 3곳을 비교했다:

- **Transistor.fm**(Justin Jackson·Jon Buda, 팟캐스트 호스팅): 마진·부트스트래핑 얘기는
  많으나 대부분 팟캐스트 인터뷰 녹취록이고, 가격/원가의 **구체적 수치**(before/after)가
  나오는 자사 블로그 글을 찾지 못했다. 후보에서 제외.
- **Baremetrics**(Josh Pigford, "Open Startup" 운동): 자기 회사 자체가 유닛 이코노믹스
  분석 도구라 메타적으로는 맞으나, 창업자가 회사를 여러 번 매각·재인수하며 서사가 복잡해
  "옮길 수 있는 무브 1개"로 좁히기 어려웠다. 후보에서 제외.
- **Plausible Analytics**(Uku Täht·Marko Saric): 자사 블로그에 날짜·MRR·팀 규모가 전부
  박힌 표가 있고, 가격 정책과 채용 정책 모두 창업자가 1인칭으로 "왜 그렇게 했는지"를
  적어 뒀다. **채택.**

대상을 중간에 바꾸지 않았다. Plausible 하나만 조사했다.

## 2. 찾은 것

### 사고의 흐름 (당사자 1인칭 — 요구사항 충족, 2건)

1차 출처 3건을 직접 열었다: 창업자 자사 블로그 `plausible.io/blog`의 세 글
(launching-plausible 2019-04-29 / june-2020-recap 2020-07-01 / open-source-saas 2022-06-22).

**무브 0 (가격 정책)**

- **처음 원칙(2019-04-29)**: "고객 입장에서 복잡한 가격 스킴은 싫다. 프리미엄 기능 없이
  트래픽량으로만 청구한다" — 출시 때부터 기능 잠금이 아니라 사용량 과금을 택함.
- **관측(2020년 상반기)**: 매출이 늘며 대형 고객이 생기자 가격을 매번 협상해야 하는
  상황이 발생.
- **추론**: "협상에 시간을 쏟는 대신 가격 곡선에 대한 단순한 공식을 만들자."
- **결정(2020-07-01 게시)**: 경쟁사 가격 조사 + 자기 직관을 근거로 "트래픽이 2배가 되면
  가격은 1.5배" 공식을 확정. 이후 협상 없이 이 공식만 적용.

**무브 1 (채용 정책)**

- **원칙**: "베이스캠프 방식을 따른다 — 아플 때까지 기다렸다가 그때만 뽑는다."
- **관측 1(2021-06)**: 기술 지원 문의 응대가 제때 안 됨 → Robert를 파트타임으로 채용.
- **관측 2(2022-02)**: GDPR 관련 이슈 이후 수요 급증으로 인프라가 못 버팀 → Cenk 채용.
- 두 채용 모두 "매출이 늘어서 미리"가 아니라 "실제로 감당이 안 돼서 그때" 이루어졌다.

### 자기보고 외 확인 (§7.1 — 확인 불가를 양성으로 접지 않기)

- `plausible.io`를 2026-09-23 직접 조회했다 → 로그인·가격·라이브 데모가 있는 **실제
  운영 중인 서비스**. `outcome_status=active`의 비자기보고 확인.
- 다만 같은 조회에서 **2019년 원칙이 지금은 완화**된 것을 확인했다: 팀 협업·API·
  이커머스 매출 추적 등은 Growth/Business 플랜에서만 열린다. 트래픽 기반 기본 과금은
  유지되지만 "프리미엄 기능 절대 없음"은 지금 기준으로는 사실이 아니다. 이 사실을
  케이스 단위 근거(evidence, move=null)로 남겨서 무브 0 claim이 지금 시점을 과장하지
  않도록 했다.

## 3. 못 찾은 것 — 확인 불가

- **비자기보고 수치 출처 0건.** 비상장 부트스트랩 기업이라 공시가 없다. Failory 인터뷰,
  Tiny Empires 뉴스레터 등 제3자 글도 결국 창업자 발언을 받아쓴 것이라 `is_self_reported`
  축을 낮추지 않았다(그게 규칙이 경고하는 함정). Tiny Empires 글(tinyempires.substack.com)은
  본문 접근이 403으로 막혀 직접 인용을 확인하지 못했다 — 사용하지 않았다.
- 그래서 두 무브 모두 **사실확인 등급 C**(자기보고 1차뿐, 다른 원 관측 없음)다.
  `outcome_direction=positive`라 발행 게이트 CG-1(등급 C는 본문에 출처 귀속 문구 필요)만
  걸리고, Cydoc처럼 발행 자체가 막히지는 않는다.
- **서버·인프라 비용의 절대 금액**: ClickHouse 마이그레이션(2020-06)이 "최선의 기술
  결정"이라고만 서술되고, 마이그레이션 전후 서버비 절감액은 확인 불가.
- **고객당 CAC·이탈률**: "유료 광고 예산 $0, 콘텐츠 마케팅과 입소문"이라고만 나오고
  구체 CAC 수치는 확인 불가.
- **급여 수준**: "매출이 없어 18개월간 무급, $50,000 이상 개인 저축을 썼다"까지만
  확인되고, 이후 급여 액수는 확인 불가.
- **지금(2026) 팀 규모·매출**: WebSearch로 "2024년 ARR $3.1M, 팀 4인 안팎"이라는 3차
  요약이 나왔으나, 원문 블로그에서 직접 확인하지 못해 초안에 넣지 않았다. 필요하면
  후속 조사거리.

## 4. 어휘 관련 메모

- `reader_problem = PRICE_TOO_LOW` — "팔리긴 하는데 남는 게 없다"의 반대쪽(가격을 원가에
  연동시켜 남는 돈을 지켰다)이라 이 코드가 가장 가깝다고 판단했다. `SOLO_CEILING`("혼자
  감당할 수 있는 한계")도 무브 1과 어울리지만, 케이스 레벨 필드는 1개뿐이라 두 무브를
  아우르는 상위 문제(마진 방어)로 `PRICE_TOO_LOW`를 택했다.
- `lever` 두 개(PRICING · OPERATIONS)는 고정 어휘 안에 있다.
- `buyer_type = B2B`로 뒀으나, 실제 고객에는 개인 블로거도 섞여 있어 B2C 성격도 있다.
  둘 중 하나만 골라야 해서 "웹사이트/비즈니스 운영자에게 파는 도구"라는 프레이밍을
  기준으로 B2B를 택했다 — 애매함을 여기 적어 둔다.
- `price_band = LOW` — 진입 플랜이 $9~19/월로 Matomo($30/월~)보다 낮게 잡은 것이
  창업자 본인의 명시적 의도("fair and affordable prices")였다.
