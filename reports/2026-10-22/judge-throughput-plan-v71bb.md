## 2. 2차 대기 10,068건 — 숫자로 못 박은 계획

사실:
- [직접 실행 확인] 10-21 12:20Z 2차: `영역 밖(out-*) 36169건은 2차 대기에서 제외 — 대기 0건` · 그룹 `{"0":0,"1":0,"2":0,"3":36169}`. 영역 ①~⑤ 안 2차 대기는 **0** 이고 매 실행 비운다.

되돌리기로 결정할 때의 계획(제안, 미구현):
- 전제 코드 1건: out-* 은 1차 relevant 만 2차에 태우는 모드(`RELEVANCE_SECOND_OUT_OF_AREA=relevant-only`). 지금 스위치(`RELEVANCE_SECOND_SKIP_OUT_OF_AREA=off`)를 그냥 끄면 relevant 아닌 26,101건까지 탄다(+$24).
- 용량: 2차 실측 1,937건 / 40.7분 = **47.6건/분**, 단가 $1.787 / 1,937 = **$0.000923/건**(run 39505774463). 한 실행 마감 150분 → 상한 ≈ 7,100건.

- N일 = 3 (단계 상향 2,000 → 4,000 → 나머지 4,068):
  - D1: out-* relevant 2,000건(≈ $1.85, 42분). 순서 = 영역 ①~⑤ 안(0건, 항상 먼저) → 최근 유입(judged_at 내림차순) → 나머지.

  - D2: 4,000건(≈ $3.69, 84분) → 같은 재평가 → D3: 4,068건(≈ $3.75, 85분).
  - 롤백(즉시): 위 하나라도 미달이거나 Gemini 429 로 2회 연속 blocked → `RELEVANCE_SECOND_SKIP_OUT_OF_AREA` 를 비운다(원복). 판정 행은 지우지 않는다.

## 4. unknown 9,061건 재판정 — 설계와 드라이런

- 기록 자리: `second_*` 는 2차(독립 판정·자동 승인 입력) 의미가 고정돼 있어 쓰지 않는다. 새 열 5개를 제안한다(마이그 파일은 만들지 않았다 — 설계 승인 뒤):
  `rejudge_verdict text check (relevant|irrelevant|unknown)` · `rejudge_reason text` · `rejudge_model text` · `rejudge_prompt_version text` · `rejudged_at timestamptz`. 원래 `verdict` 는 덮지 않는다(insert-only 원칙 유지), 하위 사용처는 당분간 안 읽는다.

  - 오케스트레이터가 본 대표 이유 3개(선호만 있고 이유 없음 · 재현 단서 없음 · 상품명만 있어 본문 누락)는 전부 "본문 정보 부족" 묶음으로 분류된다(셀프테스트 고정) → 재판정 후보에서 뺀다. 같은 입력에 프롬프트만 바꿔도 대부분 unknown 으로 남는다고 보기 때문이다.
