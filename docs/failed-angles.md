# 실패 앵글 원장 (반증마켓 콜드스타트) — §13-2 / §17-3

반증마켓(§13-2)의 콜드스타트용 실패 사례 원장이다. 원안(CB Insights/Failory/
Kaggle/Kickstarter 자동 백필)은 전부 라이선스 문제로 폐기됐다(SP-012). 대신
**공개적으로 널리 보도된 실패 사례를 자체 문장으로 재서술**해서 수동 큐레이션한다
— 원 데이터셋의 라이선스 문제와 무관하다(원문을 베끼지 않고 사실관계만 재서술).

**이 표가 정본이다.** `failed_angles` 테이블은 이 표에서 시딩하고,
`scripts/failed-angles-sync.mjs` 가 이 표를 다시 파싱해 upsert 한다.

이 테이블은 완전히 독립된 신규 **제품 트랙** 테이블이다(§20/§21). `case_studies`/
`case_evidence`(방법론 트랙)를 참조·재사용하지 않는다.

⚠️ **AC-3(라이선스 확인 게이트)는 여기서 처리하지 않는다.** 아래 행은 전부 "공개
보도 기반 재서술"이라 원 데이터셋 라이선스 문제와 무관하다는 점만 `evidence_source`
에 명시했다. AC-3 자체(신규 소스 추가 시 라이선스 자동 확인)는 별도 후속 작업이다.

행을 추가할 때 규칙:
- `case_key` 는 소문자·숫자·하이픈만 (`^[a-z0-9-]+$`). sync 스크립트의 upsert 충돌 키.
- `source_tier` 는 이 원장에서는 전부 `공개 보도`(공개적으로 널리 보도된 사례만 다룸).
- `is_estimate` 는 재서술 과정에서 추정·해석이 섞였으면 `true`, 보도된 사실 그대로면 `false`.
- 추가 후 `node --env-file=.env.local scripts/failed-angles-sync.mjs` 재실행.
