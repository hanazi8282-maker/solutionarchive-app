## A. 기존 문서와의 관계 — 교체가 아니라 보완

### A-1. 위계

```
콘텐츠 판단 위계 (ops/roles/cmo.md): 반응률 > 발행자 결정 > 작가 기본값      ← 그대로 둔다

인사이트-추출-기준.md   무엇을 찾고 무엇을 버리나 (칼럼·스레드·대시보드 공통)   [신규·최상위]
케이스-작성-가이드.md   칼럼을 어떻게 쓰나 (칼럼·대시보드)                      [신규·최상위]
  └ 스레드로 압축할 때만
      ├ voice-guide.md         문체, 500자, 기호 금지                          [하위로 내림]
      └ threads-playbook.md    훅 카탈로그, T-체크, N-0006 실험                  [하위로 내림]

게이트
  ├ 핵심 취지 (창작 금지, 근거 없는 과장 금지)     → 칼럼·스레드·대시보드 전부
  └ 절차 (content-gate Ⅰ~Ⅴ, T-체크, CG-1/CG-2)    → 스레드에만

methodology/ 의 발행 노하우 (02-gate, threads-playbook 등) → 칼럼·스레드 모두, 도움이 될 때 계속 참고
```

새 가이드 둘은 남헌이 직접 정한 기준이라 위계의 **발행자 결정** 층에 둔다. 반응률이 뒤집으면 고친다.

### A-2. 문서마다 무엇이 바뀌나

- **`content/guides/voice-guide.md`** — 스레드 압축 규칙으로 남긴다. 바뀌는 곳은 둘이다
  - §1 "가르치지 않는다, 결론을 대신 내려주지 않는다" → 칼럼에는 적용하지 않는다. 독자가 정답을 원한다
  - §5 "마지막 한 줄은 질문" → 규칙에서 실험으로 바꾼다. 스레드 마무리는 질문과 정리를 섞고 반응률로 정한다
  - 모드 A 4단 골격의 2단(통상의 선택)은 칼럼 훅 H2(통념 반박)와 같은 장치라 그대로 둔다
- **`methodology/content/threads-playbook.md`** — 고치지 않는다. `methodology/`는 append-only 아카이브라 본문은 두고 관계만 이 문서에 적는다. 스레드 훅 `H-1`~`H-7`과 칼럼 훅 H1~H4는 별개 목록이다. 칼럼을 쓸 때도 도움이 되면 참고한다
- **`methodology/content/solfa/02-gate.md` · `pdp/02-gate.md`** — 고치지 않는다. 칼럼과 스레드 모두 도움이 될 때 참고한다. 칼럼에서 반드시 지키는 것은 진위 게이트(solfa G-9, pdp G-12)의 취지이고, 판정 절차 전체를 칼럼마다 돌리지는 않는다
- **`.claude/skills/content-gate/SKILL.md`** — 칼럼 검수 절이 없다. 추가하고, 내용은 `케이스-작성-가이드.md` §10 점검표를 그대로 쓴다
- **`scripts/case-draft-stage.mjs`**
  - CG-1(등급 C 수치에 귀속 표기) — 유지
  - CG-2(등급 D는 수치 금지) — **완화**. "본인이 밝힌", "회사가 밝힌"이 붙은 자기보고 수치는 허용하고, 귀속 없는 수치는 계속 막는다
- **`.claude/agents/sa-cmo-researcher.md` · `case-research.mjs brief`** — 독자 정의를 새 정의로 바꾸고, 조사 포인트를 `인사이트-추출-기준.md` §2로 바꾼다
- **`.claude/agents/sa-cmo-writer.md` · `scripts/cmo-daily.mjs` 작성 프롬프트** — "무브 1개 = 초안 1편"을 "케이스 1건 = 칼럼 1편 → 인사이트마다 스레드 1편"으로 바꾼다
- **`config/reader-problems.json`** — §A-3

### A-3. `reader_problem` 어휘 — 확정

지금 7개는 "만들 줄 아는데 돈을 못 번다" 쪽으로 좁다. 새 독자의 막힘은 PMF 이전 단계에 몰려 있다.

**기존 7개는 지우지 않고, 앞에 4개를 추가한다.** 지우면 이미 적힌 값을 옮겨야 하고, 추가만 하면 옮길 게 없다.
DB는 형식(대문자·밑줄)만 검사하므로 마이그레이션이 필요 없다.

- `NO_ITEM` — 무엇을 할지 못 정했다
- `NO_REAL_PAIN` — 만들었는데 아무도 절실하지 않다, 누가 돈을 낼지 모른다 (#21)
- `NO_PULL` — 써 보긴 하는데 다시 오지 않고 퍼지지 않는다
- `SCATTERED_TRIES` — 이것저것 해 봤는데 무엇이 먹혔는지 모른다

## B. 스레드 · 칼럼 · 대시보드 — 무엇이 같고 무엇이 다른가

### B-1. 같은 것

- 인사이트 판정 기준
- 창작 금지선
- 원천: 케이스 조사, 리뷰·평가·지표 조사

### B-2. 역할

- **스레드 = 1차 퍼널.** 넓게, 많이, 다양하게 던져서 어떤 인사이트와 맥락에 반응하는지 모은다
- **칼럼 = 깊이.** 더 명확한 답과 맥락을 원하는 사람이 오는 곳
- **대시보드 = 칼럼이 사는 곳.** 매일 밤 새 리뷰를 반영해 다시 쓴다

### B-3. 채널별 규격

**스레드**
- 500자, 평어체, 기호 금지 (voice-guide)
- 인사이트 1개가 1편. 칼럼 1편에서 여러 편
- 본문은 사실과 적용 중심. 나머지 맥락은 칼럼에 둔다
- 훅은 플레이북 `H-1`~`H-7`, 또는 칼럼 훅 중 한 줄로 되는 것
- 마무리는 질문과 정리를 섞고 반응률로 정한다
- 근거는 자기답글
- 검수는 기존 스레드 게이트 절차 + 사람 검수 후 발행. 자동 발행 없음
- 성공 지표: 반응률

**칼럼**
- 3,000~8,000자(공백 포함, 근거 메모 제외 — 2026-09-15 남헌이 상한을 8,000으로), 분석 칼럼 평어체
- 케이스 1건 또는 분석 1건이 1편
- 필수 5요소 전부
- 훅 H2·H3, 마무리 E1·E2
- 근거는 본문 밖 근거 메모
- 검수는 `케이스-작성-가이드.md` §10 점검표 + 사람 검수
- 지금은 내부 전용. 블로그·대시보드 공개는 나중
- 성공 지표: 내부 전용인 동안은 없다. 공개할 때 정한다

**대시보드 (`/analyze`)**
- **기본은 C안**: 분석 결과 화면 자체가 칼럼이고, 스레드는 거기서 뗀다
- ①~⑤ 중 하나라도 빠지면 **A안**(칼럼 대신 개별 결과 화면)으로 자동 전환하고 이유를 표시한다. 최종 판단은 사람
- **"매번 새로운 인사이트"의 뜻**: 매일 밤 배치로 새 리뷰를 반영해 칼럼을 다시 쓴다
- 원천은 리뷰·만족도·평가·지표 (`인사이트-추출-기준.md` §3)
- 지금 버튼으로 돌리는 추출 → 사분면 검토 → 앵글 생성 흐름은 칼럼의 재료 단계가 된다

### B-4. 독자 — 창업자용 글과 셀러용 글 (확정)

- **주 독자는 일반 창업자다.** 셀러(대시보드에서 자기 상품이나 경쟁 상품을 분석한 사람)도 가끔 본다
- **글마다 작가가 판단해 창업자용과 셀러용 중 하나로 쓴다.** 한 글에 두 독자를 섞지 않는다
- 판단 기준
  - **창업자용**: 케이스 조사에서 나온 글, 또는 리뷰 분석이라도 "어떤 아이템을 고르나, 지금 아이템을 어떻게 PMF로 가져가나"로 넓혀 읽히는 글. 할 일은 아이템을 고르거나 검증할 때의 행동이다
  - **셀러용**: 특정 상품군의 리뷰 분석에서 나왔고, 핵심이 "이 시장에서 파는 사람이 상세페이지·가격·구성에서 바로 바꿀 것"인 글. 할 일은 그 셀러의 상품에 대한 행동이다
- 칼럼 첫머리에 `독자: 창업자` 또는 `독자: 셀러`를 적는다. 나중에 반응을 독자별로 가를 수 있게 한다
- 스레드는 창업자 퍼널이다. 셀러용 칼럼에서 떼더라도 창업자가 옮길 수 있는 인사이트만 창업자 말로 바꿔 뗀다 (기본값, 반응률로 조정)

### B-5. 흐름

```
케이스 조사 ──────┐
                  ├─ 인사이트 추출 (필수 5요소 판정) ─ 칼럼 1편 ─┬─ 스레드 N편 ─ 사람 검수 ─ 발행 ─ 반응률
리뷰·평가 조사 ───┘         (독자: 창업자 / 셀러)               └─ 대시보드 화면 (내부)

반응률 ─ 어떤 인사이트·맥락·마무리가 먹히나 ─ 기준 문서 개정
```

   - 케이스 후보는 파일럿을 시작할 때 실측해서 고른다

## D. 확정 기록 (2026-09-15, 남헌)

1. **독자** — 주류는 일반 창업자, 셀러도 가끔 본다. 글마다 판단해 창업자용과 셀러용을 나눠 쓴다 (§B-4)
2. **`reader_problem` 어휘** — 기존 7개 유지 + 4개 추가 (§A-3)
3. **실패 사례** — 칼럼은 허용한다. 스레드로 뗄 때만 "부정 사례는 근거 등급 A가 아니면 발행 불가"를 적용한다
4. **methodology/ 발행 노하우** — 칼럼과 스레드 모두 도움이 될 때 참고한다 (남헌이 §A-1에 직접 추가)
5. **칼럼 분량 상한 8,000자** (§B-3, 가이드 §5) — 1차 배치 결과를 보고 결정
6. **독립 검증은 파이프라인 필수 단계** (§C-1.5) — 1차 배치 5편에서 작가 전원 자체 점검 "예"였는데 검증에서 편당 7~12건이 걸렸다
7. **소재 비율은 라운드마다 점진 수렴** (가이드 §9) — 조사 큐 신규 대상은 1인·초기 창업가 우선
8. **사고의 흐름과 적용은 조사 단계에서 각 1건 이상 필수** (`인사이트-추출-기준.md` §2) — 창업자 1인칭 서술(인터뷰·블로그·팟캐스트·실적발표 콜) 최소 1건을 열어 확보한다. 없으면 조사 미완
