> **성격**: append-only. **기존 항목을 수정하지 않는다.** 판정이 틀렸으면 지우지 말고 **아래에 반증 엔트리를 추가**한다. diff가 자산이기 때문이다.

## 0. 이 파일이 존재하는 이유

`01-methodology.md`에는 서로 충돌하는 진술이 다수 있다. 원문이 **자청(전략·효율 중심)**과 **김지우 파트장 외 실무 3인방(제작·디테일 중심)**의 공동 강의이고, 개인 계정 시점과 대행 시점이 섞여 있기 때문이다. **어느 한쪽을 버리면 정보가 손실되므로 둘 다 보존하고, 대신 "언제 어느 쪽을 쓰는가"의 판정선을 붙였다.**

솔파 아카이브와 동일하게, 이 판정선은 **전부 원문 화자들의 판단을 추출한 것**이며 원문에 명시된 규칙이 아니다(`05-provenance.md` B-3 참조).

```
[시작 상태]  P-01 ~ P-14 = 프드프의 판단을 추출한 규칙 (SEED)
     ↓  발행 → 성과 대조 → 반증/보강 엔트리 누적
[6개월 후]   P-xx = 내 데이터로 덮여쓰인 나의 판정선
     ↓
[diff]      SEED와 현재 상태의 차이 = 오리지널리티의 정량적 좌표
```

**프드프 고유의 추가 축**: 솔파 R-01~R-14와 같은 질문에 **다른 답**을 하는 지점이 있다. 그 지점은 `../cross-decisions.md`의 C-xx로 별도 관리한다. 두 SEED가 갈리는 곳이 **조건부 규칙**이고, 그 조건을 찾는 것이 이 아카이브의 최대 산출물이다.

## 1. 루프 프로토콜

솔파 `04-decisions.md`와 **동일 스키마**를 쓴다. 두 방법론의 판정 로그가 한 테이블에서 비교 가능해야 하기 때문이다.

### 1-1. 발행 전 — 판정 기록 (필수)

`02-gate.md`를 통과시키는 과정에서 **규칙을 적용한 순간마다** 엔트리를 남긴다.

기록 조건 (하나라도 해당하면 기록):
- 상충 규칙(P-01~P-14) 중 하나를 적용해 **X 또는 Y를 선택**했다
- 게이트 항목에서 **떨어질 뻔했는데 통과시켰다** (= 예외 판단)
- 규칙에 없는 새로운 판단을 했다 (→ 신규 규칙 후보)
- **솔파 규칙(R-xx)과 충돌하는 지점에서 한쪽을 택했다** (→ `../cross-decisions.md`에도 기록)

### 1-2. 발행 후 — 성과 기입 (D+7 / D+30)

측정 지표(프드프 §1-2의 반응률 4요소를 그대로 사용):

| 프드프 지표 | 의미 |
|---|---|
| **시청 지속 시간 / 끝까지 본 비율** | 본문이 작동했는가 |
| **저장 수** | 릴스에서 가장 중요한 신호(§1-3) |
| **공유 / 친구에게 보낸 수** | 두 번째로 중요한 신호 |
| **댓글 수** | 반응도의 실물 |
| **프로필 방문 / 링크 클릭** | 가치 사다리 다음 계단 진입(§8-6) |
| **문의·구매 전환** | ★ 좁은 표본 업종은 이것만 본다(§12-1) |

> ⚠️ 조회수를 1순위 지표로 삼지 않는다. 프드프 본문이 직접 경고한다 — §2-6(터지면 안 되는 계정), §12-1(5천이면 충분).

**Threads 치환**(솔루션아카이브 운용 기준): 저장 → 저장률 / 공유 → 인용·리포스트 / 댓글 → 답글 / 프로필 방문 → 프로필 클릭률.

### 1-2b. 역방향 트랙 (G-R)

솔파와 동일. 프드프에서는 역방향이 **방법론 자체의 핵심**이라는 점만 다르다 — §3-2(분석 어셈블), §7-1(**"강의에서 얻어 가야 하는 게 딱 한 가지 있다면 그건 바로 이 분석하는 습관"**).

| 트랙 | 입력 | 학습 속도 | 잡아내는 것 |
|---|---|---|---|
| **정방향** | 내 발행 → 성과 | 1건 / 30일 | 내 판정이 **맞았는지** |
| **역방향** | 남의 터진 글 | 5건 / 세션 | 내 규칙에 **구멍이 있는지** ★ |

**권장 비율**: 프드프는 **발행 1건당 역방향 5건 이상**을 권한다(솔파는 3건). 근거 — **"정말 영상을 10시간 걸려서 하나를 만드는 것보다 잘된 영상을 10개 보고 스스로 분석을 해본 다음에 한 20~30분 걸려서 하나 만드는 게 훨씬 낫습니다."**(§5-8)

### 1-3. 판정 검증 — 규칙 갱신

| 마킹 | 조건 | 후속 조치 |
|---|---|---|
| `유효` | 성과가 판정 방향과 일치 | 규칙 신뢰도 +1 |
| `무효` | 성과가 판정 방향과 반대 | **반증 엔트리 추가.** `## 3. 규칙 갱신 이력`에 append |
| `보류` | 다른 변수가 지배적이라 귀속 불가 | 기록만 남김 |

### P-01. 형식 모방 필수 vs 베끼면 안 됨

| | 진술 |
|---|---|
| **X** | §2-1 — **"그걸 그대로 올리면 베끼는 거. 그거는 문제가 되는 거고, 근데 그걸 제 식으로 풀어 쓰는 거예요."** / **"형식을 모방하라는 거예요."** |
| **Y** | §3-6 — **"특히 틱톡 같은 경우에 100만 넘는 사람들은 서로 베끼는 게 문화예요. (…) 이 영역은 거의 베끼셔도 아무도 뭐라고 하는 사람 없고"** |

**판정선**
- **플랫폼 분기**: 틱톡·릴스의 유행 형식(음원·챌린지·POV·전환 형식) → Y 허용. **내용·카피·기획** → X 적용.
- **판별 질문**: 내가 가져오는 것이 **형식**인가 **콘텐츠**인가. 음표는 형식, 멜로디는 콘텐츠.
- 원문의 유일한 정합점: **"작곡가들이 그 음표 쓰고 기존 형식에 발라드를 한다고 해서 너 발라드 100년 전에 그 사람 거 베꼈네? 이렇게 안 한단 말이에요."**

**Threads 치환** — 구조(첫 문장 형식·문단 리듬·나열 방식)는 빌려도 되고, 관점·사례·결론은 내 것이어야 한다.

`SEED` `신뢰도: 0` `반증: 0`

### P-02. 템플릿 1분이면 끝 vs 기획이 훨씬 중요

| | 진술 |
|---|---|
| **X** | §10-1 — **"할머니도 3분, 5분 만에 릴스를 만들어서 조회수 10만을 찍을 수 있다"** / 템플릿 실측 15만·16만·22만 |
| **Y** | §5-8 — **"기술보다는 이 기획이라는 게 훨씬 더 중요하거든요."** / §10-1 — **"내가 마음대로, 지 멋대로 우리 집 안방을 찍어가지고 올린다고 조회수가 나오진 않아요."** |

**판정선**
- **층위 분리**: 템플릿은 **제작 비용**의 문제, 기획은 **터질 확률**의 문제다. 둘은 대체 관계가 아니다.
- **단계 분기**: 시작 단계 → X(일단 올려야 레벨업이 시작된다, §10-1). 성과를 원하는 단계 → Y.
- 원문 봉합: **"물론 이제 공식을 아셔야 돼요."**

**Threads 치환** — 발행 마찰을 줄이는 것(템플릿·포맷 고정)과 기획을 대충 하는 것은 다르다.

`SEED` `신뢰도: 0` `반증: 0`

### P-03. 표본을 넓혀라 vs 포지셔닝을 좁게 ★ 가장 자주 호출됨

| | 진술 |
|---|---|
| **X** | §2-3 — 표본 이론. **"모든 콘텐츠와 모든 사업 아이디어는 표본이 넓어야 된다"** / 1만 → 110만 (100배) |
| **Y** | §8-4 — **"극손상모, 복구펌, 탈색머리 펌 전문 (…) 이렇게 포지션을 좁게 가져가시는 것이 좋습니다."** / §12-1 — **"조회수가 500, 1000, 5000만 나와도 떼돈을 벌 수가 있죠."** |

**판정선 (층위가 다르다 — 원문이 정리하지 않은 것을 이 문서가 분리)**

| 층위 | 방향 | 근거 |
|---|---|---|
| **콘텐츠 카피(알고리즘 확산)** | **넓힌다 (X)** | 알고리즘은 관심 없는 층까지 뿌려야 100만이 된다(§1-5 5단계) |
| **프로필 이름·소개글(검색 진입)** | **좁힌다 (Y)** | 검색하는 사람은 이미 구매 의도가 있다. 경쟁도가 낮은 곳을 잡는다(§8-4) |
| **목적이 조회수** | 넓힌다 | |
| **목적이 매출·문의** | 좁혀도 된다 | 미용 디자이너 월 3,500만 / 식기세척기 2억 5천(§12-1) |

- **병행 실증**: 미용 디자이너는 프로필은 좁게(탈색머리 펌 전문), 카피 하나는 넓게(미용실 상담 3가지 = 86만) 갔다. → §11-5.
- 실행 문장: **"조회수는 넓히고, 검색 진입은 좁힌다."**

**Threads 치환** — 계정 소개는 뾰족하게, 개별 글의 첫 문장은 넓게.

### P-04. 무조건 터뜨려라 vs 터지면 안 되는 계정

| | 진술 |
|---|---|
| **X** | §3-1 — **"이 14가지 공식을 이해하시면 릴스가 잘될 수밖에 없습니다."** |
| **Y** | §2-6 — **"라보 스테이크가 있어 이거는 터뜨리면 안 되거든요."** / **"자청 제 인스타그램도 터지면 안 돼요."** |

**판정선**
- **계정 유형 분기**: **제품 판매형**(더비랩·이별사수·북타쿠) → X. **개인 노출형** 또는 **고급 브랜딩** → Y.

- 대체 지표: Y를 택하면 조회수 대신 **전환·문의·브랜딩 밀도**를 본다(79만 브랜딩 > 300만 조회수, §2-6).

**Threads 치환** — 도달을 목표로 할 글과 신뢰를 목표로 할 글을 구분한다. 후자는 좁게 닿는 게 낫다.

### P-06. 자아 흠집 내기 vs 모욕 금지

| | 진술 |
|---|---|
| **X** | §4-6 — **"1억도 못 모았다면 무조건 봐야 하는 경제책 4권"** / **"벤치 100kg 못 들면 운동 접으라고?"** |
| **Y** | §4-6 — **"'너 100억도 못 모았지? 나보다 멍청하네' (…) 모욕을 주는 거기 때문에 문제가 될 수 있죠."** |

**판정선 (원문이 유일하게 명시적으로 제시한 판정선)**
- **극복 가능한 것을 건드리면 자아 흠집(허용), 극복 불가능한 것을 건드리면 모욕(금지).**
- 예: 자산·근력·실력 = 극복 가능 → 허용 / 키·외모·출신 = 극복 불가능 → 금지
- **숫자의 임계값 설계**: **"이게 200kg였으면 집중이 안 돼. 근데 100kg는 내가 닿을락 말락 하고 애매한 숫자"** → 닿을락 말락 해야 한다.
- 화자 본인의 사용 제한: 유명해진 뒤에는 쓰지 않는다.

**Threads 치환** — 독자가 노력으로 바꿀 수 있는 것만 건드린다.

### P-10. 감성·미적 요소가 결정적 vs 디자인 하지 마라 ★

| | 진술 |
|---|---|
| **X** | §1-9 / §3-11 — **"인스타그램은 (…) 미적인 요소가 굉장히 중요한 플랫폼"** / 꽉 찬 화면 미준수 시 조회수 몇 배 손실 |
| **Y** | §7-5 ④ — **"디자인 절대 넣지 마세요. 그냥 인스타에서 제공하는 기본 글꼴이랑 음악만 사용하셔도 충분합니다."** |

**판정선**
- **구분선은 "화려함"이 아니라 "깔끔함"이다.** 원문: **"릴스는 진짜 이미지가 되게 중요한 플랫폼이기 때문에 조금이라도 아마추어처럼 보이는 순간 이탈이 일어납니다."**
- 즉 X와 Y는 같은 목적(아마추어로 보이지 않기)의 두 수단이다. 감각이 없는 사람이 디자인을 시도하면 **오히려 아마추어로 보인다.**
- **단계 분기**: 초보 → 기본 글꼴 + 템플릿 + 화면 전환 최소화. 감각이 붙은 뒤 → 어셈블로 감성 요소를 따라 한다(§3-11 — **"감성이나 이런 영역들도 우리가 충분히 따라 할 수 있어요"**).
- 절대 지켜야 할 것: **꽉 찬 화면**(§1-9) — 이건 디자인이 아니라 규격이다.

**Threads 치환** — 서식·이모지·구분선을 꾸미지 말고, 대신 줄바꿈·문단 길이 같은 규격만 지킨다.

**Threads 치환** — 알고리즘 조작 시도의 판정선. 남의 글을 실제로 읽고 반응하는 것과 노출을 사려는 것은 다르다.
