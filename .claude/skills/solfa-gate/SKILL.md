# solfa-gate

솔파(윤성원) 콘텐츠 방법론의 발행 전 검증 게이트를 실행한다.
정본은 `methodology/content/` 이고, 이 스킬의 `references/` 는 그 복사본이다
(동기화: `scripts/sync-solfa-skill.sh`).

## 정방향 (내 초안 검증)

1. `references/02-gate.md`를 읽고 G-0부터 **순서대로** 판정한다
2. 떨어진 항목이 나오면 **거기서 멈춘다.** 뒤 항목은 보지 않는다.
   되돌아갈 지점(§번호)을 지시한다. 문장 수정 제안 금지 — G-1 탈락에 문장을 다듬는 건 최악의 실패 모드다
3. 규칙 충돌 시 `references/04-decisions.md`의 R-01~R-14를 적용한다
4. G-3에서 막히면 `references/03-excerpts.md`의 B-1(반례 9종)에서 구조를 제안한다
5. 출력 마지막에 **판정 로그 엔트리를 복사 가능한 코드블록으로** 제시한다.
   `출처: 자체발행` 플래그와 **예측** 칸을 반드시 채운다 — 예측이 없으면 D+30에 아무것도 학습되지 않는다

## 역방향 (G-R, 남의 콘텐츠 분석)

1. `references/02-gate.md`의 G-R 섹션 절차를 따른다
2. **댓글·인용문 실물**을 근거로 채운다. 추측으로 채우면 의미 없음을 사용자에게 알린다
3. 핵심 판정 — "내 게이트로 이 글을 탈락시켰겠는가"를 반드시 낸다
4. `구멍`이면 `## 5. 신규 규칙 후보` 엔트리를 함께 출력한다
5. `출처: 외부관찰` 플래그를 단다

> **현재 상태**: `references/02-gate.md`에 G-R 섹션이 아직 없다(G-0~G-10 + 부록만 존재).
> 역방향 요청을 받으면 절차를 지어내지 말고, G-R 절차가 아직 문서화되지 않았음을
> 사용자에게 알리고 어떻게 할지 물어라.

## 공통 금지

- 게이트 항목을 건너뛰지 않는다
- 통과 여부를 애매하게 남기지 않는다. 각 항목은 통과/탈락/예외통과 셋 중 하나로 명시
- 예외통과는 항목을 명시하고 신규 규칙 후보로 기록한다

## 로그 기록

판정 로그를 실제로 파일에 남길 때는 **정본**인 `methodology/content/04-decisions.md`의
`## 4. 판정 로그`에 append 한다. `references/` 복사본에 쓰지 않는다.
`## 2. 규칙 SEED`는 수정 금지 — 갱신은 `## 3. 규칙 갱신 이력`에 append.
