역방향 관찰을 한 세션 돈다. 대상: $ARGUMENTS

⛔ 발행하지 않는다. 남의 계정에 좋아요·팔로우·답글을 남기지 않는다. **읽기만 한다.**

## 왜 이걸 하는가

정방향(내 발행 → 성과)은 **30일에 1건**밖에 학습되지 않는다. 역방향은 **한 세션에 5건**이다.
그리고 정방향으로는 원리적으로 발견할 수 없는 것을 잡는다 — **내가 탈락시켰을 글이 실제로는 잘된 경우.**
탈락시킨 글은 발행되지 않아 데이터가 남지 않기 때문이다.

`02-gate.md` 권장 비율: **발행 1건당 역방향 3건.** 지금까지 이게 안 돌았던 이유는 의지가 아니라
댓글 실물을 읽는 손이 많이 가서였다(U-3 예외통과 기록 `NEW-20260907-01` 이 증거다).
**읽는 것만 사람/브라우저가 하고, 나머지는 전부 스크립트가 한다.**

## 대상 선정 — URL 이 안 주어졌을 때

| 고른다 | 뺀다 |
|---|---|
| 내 영역과 **인접**하되 내가 안 쓸 것 같은 글 | 이미 내가 잘 아는 포맷 |
| **이유를 모르겠는데 잘된 것** ★ | 이유가 뻔한 것(팬덤·시의성 폭발) |
| 내 취향이 아닌 것 | 광고·협찬 등 외부 트래픽 유입 건 |

⚠️ **팬덤 도달은 제외한다**(R-05). 유명해서 잘된 건 학습 재료가 아니다.
판별법: **조회수 ÷ 팔로워**를 본다. 이 값이 크면 팬덤 밖으로 나간 것이고, 작으면 팬덤 안에서만 돈 것이다.
(기준 사례: `@lecor_txt` 는 2.5만 팔로워에 도달률 3~7% 였다 — 팬덤 폭발이 아니라 **반응률** 사례였다.)

## 절차

### 1) 화면에서 읽는다 — 이 단계만 사람/브라우저가 한다

각 URL 을 열고 **화면에 찍힌 값 그대로** 읽는다. 포스트 하단 4개 숫자는 순서대로
**좋아요 · 답글 · 리포스트 · 공유**다. 조회수는 본문 위 "조회 N회".

읽을 것:
- 조회 / 좋아요 / 답글 / 리포스트 / 공유
- 계정 팔로워 수 (프로필 1회만)
- 연재라면 **각 편의 좋아요** (이탈 곡선이 여기서 나온다)
- ★ **답글·인용문 실물** — 이게 R-0(사람들이 무엇을 느꼈나)·R-6(퍼갈 이유)의 유일한 근거다

> **추측으로 채우지 마라.** 인용문을 못 읽었으면 `quotes` 를 비워 둔다.
> 스크립트가 "인용문 미확보"로 표시하고, 그 건은 R-0·R-6 이 빈 채로 적립된다.
> 빈 것이 틀린 것보다 낫다 — `02-gate.md` G-R: *"내 추측으로 채우면 아무 의미가 없다."*

### 2) 양쪽 게이트를 다 돌린다

★ 정방향과 결정적으로 다른 지점이다. 역방향은 **솔파와 프드프를 둘 다** 돌린다.
`.claude/skills/content-gate/SKILL.md` 「역방향」 절을 따른다.

핵심 질문은 하나다:

```
이 글을 내가 썼다면, 어디서 떨어뜨렸겠는가?
  → 떨어뜨릴 곳 없음        = 내 규칙과 정합. 신뢰도 +1
  → 둘 다 탈락              = ★ 양쪽 공통 구멍
  → 한쪽만 탈락             = ★★ 조건부 규칙의 증거 (cross-decisions.md 갱신 대상)
```

### 3) JSON 으로 적는다

```json
{
  "session_date": "2026-09-13",
  "observations": [
    {
      "url": "https://www.threads.com/@lecor_txt/post/XXXX",
      "handle": "lecor_txt",
      "posted_at": "2026-07-09",
      "title": "SNS 천재들 특",
      "type": "리스트",
      "part": "1/2",
      "length": "단문+댓글",
      "style": "음슴체",
      "move": "정체 규정 + 부연 분리",
      "followers": 25000,
      "views": 1800,
      "likes": 298,
      "replies": 37,
      "reposts": 45,
      "shares": 7,
      "quotes": ["실제 답글·인용문을 그대로"],
      "solfa_verdict": "통과",
      "pdp_verdict": "탈락:G-7",
      "note": "한 줄 관찰"
    }
  ]
}
```

- `type`: `리스트` | `짧은통찰` | `장문연재` | `서사`
- `solfa_verdict` / `pdp_verdict`: `통과` | `탈락:G-x` | `예외통과:G-x` — **둘 다 필수**
- 못 읽은 수치는 **넣지 않는다**(0 을 넣지 마라. 0 과 미확인은 다르다)

### 4) 적립한다

```bash
node scripts/gr-observe-append.mjs /tmp/gr.json --dry-run   # 검증만
node scripts/gr-observe-append.mjs /tmp/gr.json             # 실제 적립
bash scripts/sync-content-skill.sh                          # references 동기화
```

스크립트가 하는 일:
1. `methodology/content/gr-observations.jsonl` 에 append (기계 정본, **같은 URL 은 자동으로 건너뛴다**)
2. `methodology/content/threads-playbook.md` 의 **§1 코드표**(T-코드 자동 채번)와
   **§3-0 실측표**(좋아요율·도달률 자동 계산)에 행 추가
3. `reports/gr/<날짜>-gr-entries.md` 에 판정 로그 엔트리를 **붙여넣기 대기**로 생성

입력이 하나라도 틀리면 **한 건도 쓰지 않는다.**

### 5) 로그를 붙인다 — 이 단계는 사람이 확인한다

스크립트는 `04-decisions.md` 에 직접 쓰지 않는다. SEED 보호 구역이기 때문이다.
`reports/gr/<날짜>-gr-entries.md` 를 열고 각 엔트리의 **적재 위치**대로 옮긴다.

| 판정 | 적재 위치 |
|---|---|
| 둘 다 통과 | `methodology/content/pdp/04-decisions.md` `## 4. 판정 로그` |
| 둘 다 탈락 ★ | 양쪽 `04-decisions.md` + `## 5. 신규 규칙 후보` (`발견 경로: 외부관찰(G-R 구멍)`) |
| 한쪽만 탈락 ★★ | `methodology/content/cross-decisions.md` **갱신 대상** |

## 보고

- 적립 건수 / 중복 건너뜀 / **구멍 발견 건수**
- 인용문 미확보 건수 (있으면 그 사실을 숨기지 말고 적는다)
- 새로 붙은 T-코드 범위
- `reports/gr/<날짜>-gr-entries.md` 경로와 "붙여넣기 대기: N건"
- 구멍이 나왔으면 **무엇이 구멍인지 한 줄** — 그게 이 세션의 유일한 산출물이다

## 하지 않는 것

- 남의 계정에 반응을 남기지 않는다
- `## 2. 규칙 SEED` 를 수정하지 않는다
- 인용문을 추측으로 채우지 않는다
- 팬덤 도달 사례를 학습 재료로 적립하지 않는다 (R-05)
- 한쪽 게이트만 돌리지 않는다 — **역방향은 양쪽이다**
