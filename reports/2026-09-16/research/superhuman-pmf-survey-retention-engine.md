# 조사 노트 — superhuman-pmf-survey-retention-engine (Superhuman)

큐 사유: `coverage_gap` — RETENTION 승인 케이스 0곳, 매칭 성립에 3곳 필요. 대상 미정 → 직접 선정.

## 대상 선정

기존 적립 slug 33개를 확인 — RETENTION 병목의 성공 사례가 없었다(실패 사례는
`fab-com-curation-retention-collapse` 로 이미 있음). Chewy(`chewy-autoship-retention`)와
Duolingo(`duolingo-streak`)가 이미 리텐션 계열을 선점하고 있어, 다른 업종·다른 메커니즘의
성공 사례가 필요했다. Superhuman(이메일 생산성 SaaS, 창업자 Rahul Vohra)을 선정했다 —
"제품을 더 좋게 만들었다"가 아니라 "리텐션을 재는 방법 자체를 바꿨다"는, 다른 사례와
겹치지 않는 각도이고 창업자 1인칭 기고문·팟캐스트가 풍부해 사고의 흐름을 채울 수 있었다.

## 답변 순서대로

1. **독자 문제 (reader_problem)**: `ONE_OFF_ONLY` — 어휘 목록에 "구독 서비스인데 사용자가
   붙어 있는지 애매하게 걸쳐 있는지 모른다"에 정확히 맞는 코드는 없다. `ONE_OFF_ONLY`(재구매·
   구독으로 못 넘어간다)로 두었다 — 붙잡아야 할 사람이 지금 붙어 있는지조차 모르는 상태도
   "재구매 전환이 안 되는" 문제의 상위 범주로 판단했다. 더 정확한 코드가 없다는 점은 명시해 둔다.

2. **transfer_note 한 줄**
   - 무브1(PRODUCT_FEATURE): 최근 2~4주 안에 핵심 기능을 실제로 쓴 사용자에게 "이 제품을 더
     이상 못 쓰게 되면 기분이 어떨까요?"(매우 아쉽다/조금 아쉽다/별로 안 아쉽다) 설문을
     오늘 보내고, "조금 아쉽다"를 고른 사람에게만 이유를 추가로 묻는다.

3. **preconditions**: 최근 실사용자 명단 + 이메일 채널(자본·인력 부담 낮음). 응답 40명
   미만이면 비율을 믿지 말고 다음 분기로 미룬다 — 이 숫자는 Vohra 본인이 인터뷰에서 언급한
   통계적 유의성 기준이다.

3.5. **사고의 흐름 (1인칭 출처, 총 3건 확보 — 요구치 1건 초과, 전부 동일 원 관측)**
   - Rahul Vohra, First Round Review 기고문(2018-11-13): "기존 PMF 정의(입소문·자금조달
     용이성 같은 사후 지표)로는 지금 뭘 고쳐야 하는지 실행 불가능하다"는 관측 → "측정할 수
     있으면 최적화할 수 있다"는 추론 → Sean Ellis 의 선행지표 설문(40% 벤치마크) 채택이라는
     결정.
   - 같은 글이 Superhuman 공식 블로그(2018-11-27)에도 저자 본인 이름으로 재게재됨 — 수치
     동일(22%→33%→58%).
   - SaaS Club 팟캐스트 인터뷰(2023-02-09, 육성): 22%→33%→47%→56%→58% 로 이어지는 분기별
     중간값을 직접 구술 — 기고문에는 없는 세부 경로(분기별 값)까지 1인칭으로 확인했다.
   - 셋 다 **같은 원 관측**(2017~2018년에 실시한 동일 PMF 서베이 결과)을 반복 서술한 것이라
     `observation_key`를 동일하게 두었다 — 독립 확인 3건으로 세지 않았다(§7.1, L-60 규칙).

4. **무브 1건** — `PRODUCT_FEATURE`. "설문 세분화 → 로드맵 50/50 재분배"라는 프로세스 변경을
   가장 가까운 어휘인 PRODUCT_FEATURE 로 분류했다. 정확히는 "제품 개선 프로세스"에 가깝고
   고정 어휘(LEVER)에 이 개념이 따로 없다 — 어휘 밖이라 억지로 고른 것임을 밝혀 둔다.
   병목은 `RETENTION` 하나로 건다.

5. **수치·출처**: PMF 서베이 "매우 실망" 응답 비율 22%→58%(%, 2017-07~2018-04 약 3분기).
   출처 3건 모두 Vohra 본인의 자기보고(1차)이고, 서로 다른 매체이지만 같은 관측이라
   `fact_check_grade`는 C("자기보고 1차뿐 — 다른 원 관측 없음")다. `gradeMove`(독자 인사이트
   축)는 구체적 행동+전제+근거가 모두 있어 A.

6. **outcome_status**: `active`로 표기했다 — Superhuman 은 2025-07-01 Grammarly 에 인수됐고,
   Grammarly Inc 자체가 2025-10-29 "Superhuman Platform Inc" 로 사명을 바꿔 Superhuman 을
   제품군의 한 축(Superhuman Mail)으로 계속 운영 중이다(2026-02 Rows 인수 등 후속 확장까지
   확인). 독립 회사로서는 끝났지만 제품·브랜드가 죽지 않았으므로 `shutdown`이 아니고, 운영
   지속을 확인했으므로 `unknown`도 아니라고 판단했다. `acquired`라는 별도 값이 OUTCOME_STATUS
   어휘에 없어 가장 가까운 `active`를 골랐다는 점은 검수 시 재확인이 필요하다.

## 이 어휘에 없는 것

- `reader_problem`: "지금 붙어 있는 고객이 진짜 붙어 있는지 모른다"에 정확히 맞는 코드 없음.
- `LEVER`: "제품 개선 프로세스/측정 체계 자체를 바꿨다"에 맞는 코드 없음(PRODUCT_FEATURE로 대체).
- `OUTCOME_STATUS`: "인수됐지만 브랜드·제품은 살아 있다"에 맞는 코드 없음(active로 대체).

## 못 찾은 것 (확인 불가로 남긴 항목)

- **독립된 원 관측 2건째**: 22%→58% 수치를 Vohra 본인이 아닌 제3자(예: 투자자, 내부 데이터
  공개, 감사)가 별도로 확인한 자료를 찾지 못했다. 스타트업 비상장사 특유의 한계로, 이 무브는
  구조적으로 `fact_check_grade` A에 도달하기 어렵다 — 발행 게이트는 이 무브를 통과 못 시킨다
  (출처 귀속 문구를 본문에 넣는 조건으로 C 등급 발행 대기까지는 갈 수 있음, `docs/evidence-rules.md`
  대조는 사람 검수 시 재확인 필요).
- **PMF 서베이 결과의 정확한 일자**: "2017년 여름", "3분기 후"라는 표현만 확인했고 정확한
  연-월-일은 원문에 없다 — `observed_period_start/end`를 분기 단위 근사치(2017-07-01,
  2018-04-01)로 채웠다. 정밀한 날짜가 아니라 근사임을 명시한다.
- **2018년 이후 리텐션·NRR 실측치**: 웹서치 과정에서 "90%+ 연간 리텐션, 120%+ NRR"이라는
  수치를 발견했으나 원 출처(어느 보고서·어느 시점인지)를 특정하지 못해 초안에 넣지 않았다
  — 근거 없는 숫자를 적지 않는다는 원칙(§4) 때문에 뺐다.
- **매출·가격 변동의 정확한 시점**: `price_band`를 HIGH로 판단한 근거는 $30/월 안팎이라는
  일반적으로 알려진 가격대이며, 이 초안의 무브와 직접 연결된 수치는 아니라 evidence 로
  올리지 않았다.

## 검증

```
node scripts/case-research.mjs validate --slug superhuman-pmf-survey-retention-engine
```
→ **exit 0**. 무브 1건, 근거 3건, `gradeMove` 등급 A 1건 / `fact_check_grade` C 1건(위 사유).
경고(warn) 0건, error 0건.
