# CLAUDE.md §10.1 개정 초안 — 차단 신호가 오면 무인 루프가 v70 소스를 끈다 (L-34 #5)

상태: **초안만. 적용하지 않는다.** 남헌이 직접 헌법을 수정한 뒤 "헌법 개정 완료"라고 알려 주기 전까지 현행 §10.1 이 그대로 유효하다(제1참모 2026-10-14). CC 는 CLAUDE.md 를 직접 편집하지 않는다.

## (가) 예외 조항 문구 초안

§10.1 "허용 (무인 루프가 스스로 한다)"의 **"발굴 적재"** 항목 끝, `무인 루프는 review_sources 에 INSERT/UPDATE 하지 않는다` 문장 뒤에 아래 불릿을 더한다.

> - **차단 시 즉시 정지**(남헌 2026-10-14, v70 §1-3) — 무인 루프는 `review_sources.enabled` 한 칸만, **`true → false` 방향으로만**, 다음 조건이 **모두** 맞을 때 쓸 수 있다.
>   1. 대상은 `override='owner_2026-10-14'` 인 소스(v70 임시 소스)뿐이다. 그 밖의 소스(남헌이 속도·예외를 따로 정한 앱스토어·구글 플레이·다나와 등)는 대상이 아니다.
>   2. 사유가 기술 차단 신호다: 같은 소스가 차단 응답(`blocked_responses>0` — 403/429/캡차/빈 응답/`/sorry/`)을 낸 정기 실행 1회 뒤 **soft-skip 상태가 연속 3개 정기 슬롯 이상 유지**됨, 또는 사이트의 중지 요청·경고·법적 통지를 사람이 Notion 에 올린 경우. 일시적 5xx·타임아웃은 사유가 아니다.
>   3. 쓰기 전에 `disabled_reason` 에 사유와 실행 URL 을 적는다(`review_sources_disabled_needs_reason` CHECK 가 강제) — 같은 UPDATE 에서 `disabled_at` 도 쓴다.
>   4. 쓴 즉시 Notion 일일 상태 로그에 행을 올린다. `사람판단필요` 는 사유가 **중지 요청·경고·법적 통지**일 때만 `true`, 단순 차단 정지는 `false`(막힌것·다음할일과 브리핑 "꺼진 소스" 칸에 적는다). 켜는 것은 어느 쪽이든 사람만 한다. 켜기·`override` 변경·`health` 변경은 이 예외에 없다.
>   5. 되돌리기: 사람이 `enabled=true` 로 되돌린다. 기계는 다시 켜지 않는다(한 방향).
>   6. 구현은 `scripts/` 한 파일에 모으고 UPDATE 대상 칸을 코드로 제한한다(`enabled`·`disabled_reason`·`disabled_at`), 셀프테스트가 이 제한을 고정한다.

**보정 이유 (v71b §6, 남헌 2026-10-14)**
- 조건 2: 처음 문구("연속 2개 정기 실행 blocked_responses>0")는 PR #518 의 soft-skip 과 같이 성립하기 어렵다 — 차단 1회 뒤 그 소스는 다음 실행부터 건너뛰어져 두 번째 차단 응답이 나올 수 없다. 그래서 "차단 1회 + soft-skip 3슬롯 유지"로 바꿨다(차단이 일시적이 아니라 고착됐다는 뜻을 같은 정보량으로 센다).
- 조건 4 대안 비교 (결정은 남헌):
  - 안1 — 단순 차단도 `사람판단필요=true`(원안): 놓치지 않지만 §11 기준("막힘 사실은 false")과 어긋나고, 소스가 늘수록 사람 판단 큐가 차단 알림으로 채워진다.
  - 안2 — 통지(중지 요청·경고·법적 통지)만 true, 단순 차단은 false + "꺼진 소스" 칸(**위 본문의 선택**): §11·§10.2 예외 목록(새 법적 리스크)과 일치하고 큐가 덜 흔들린다. 대가: 꺼진 소스 칸을 사람이 정기적으로 봐야 한다.
  - 안3 — 단순 차단은 로그 행 없이 브리핑 "꺼진 소스" 칸만: 가장 조용하지만 꺼졌다는 사실이 일일 상태 로그에 남지 않아 추적이 끊긴다. 권장하지 않는다.

(선택) §10.1 "금지" 절의 `무인 루프에는 … 권한이 없다` 문단 맞은편에 한 줄: "예외: 위 '차단 시 즉시 정지'".

## (나) 예외가 없을 때 불편했던 구체 사례 (2026-10-13~14 실측)

1. **indiehackers 403 반복 — 잡이 연속 빨간불.** 정기 실행 run 38369519381(10-13 08:28Z)과 38435306545(10-13 17:01Z)가 같은 소스의 403(`board:stories`, 램프 "같은 단계 7회째 차단·14일 동결")로 `exit 1`. 소스는 `enabled=true` 그대로라 다음 슬롯도 1요청을 또 보낸다. 사람이 끄기 전까지 매 슬롯 반복 + "잡 실패" 경보가 소스 하나 때문에 계속 울려 진짜 실패를 가린다(§7.2).
2. **임시 대응(soft-skip)의 한계.** PR #518 이 차단 다음 실행부터 읽기 전용으로 건너뛰게 했지만(`HALT_ON_BLOCK_SOURCES`), `review_sources.enabled` 는 켜진 채라 대시보드·`/agents`·source-health 리포트에서 "켜짐 + 최근 차단"으로 보인다. "꺼진 소스"와 "차단돼 건너뛰는 소스"가 사람 눈에 구분되지 않는다. 재개 경로도 `--source=<키>` 수동 실행뿐이다.
3. **8시간 무인 중 통지 대응 불가.** 사이트의 중지 요청·경고가 와도 무인 루프가 소스를 끌 방법이 없어 사람이 깰 때까지 수집이 계속된다(v70 §9-4 정지 조건과 §10.1 의 충돌). soft-skip 은 "차단 응답"에만 반응하고 "통지"에는 반응하지 않는다.
4. **ok 로그 오해 — 꺼진 소스의 `status=ok` 실행 기록.** producthunt·todayhumor(`enabled=false`)가 7일간 방문 타깃 0·`status=ok` 실행 기록 14건을 남겼다(조사 2). 끈 소스가 "정상 가동"으로 읽힌다 — 끄는 행위의 기록이 별도 이벤트로 남지 않아 생긴 혼선이다.
5. **Fable 검수 #5.** 차단(403)을 받아도 소스가 안 꺼진다는 점이 높음(심각도)으로 지적됐다.
