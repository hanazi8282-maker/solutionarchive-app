```
클로드 코드에게 시키기만 하면 될 줄 알았는데, 결국 작업 노가다를 해야만 합니다.

원하는 서비스를 자동화 시키고 있었는데, 그냥 딸깍으로는 안되더군요. 직접 로직은 검토하고,  엔진을 짜고 돌리기 전에 직접 로직대로 시뮬레이션을 돌려보았습니다. 서로 다른 13개 업종, 14개 케이스를요.

이유는 하나였습니다. 코드로 만들면 틀려도 그럴듯하게 돌아갑니다. 그리고 클로드는 그럴듯한 답변을 말하죠 하지만 진짜로 멋진 코드가 만들어 지고 있을까요?

14번을 돌리고 나니 결함이 우후죽순 나왔습니다. 다행이 핵심코드는 문제가 없었지만 디테일에서 문제가 많았죠. 클로드에게 시키면 전부 다 되는 세상이기에 우리는 ai를 너무 믿고 있는 것 같습니다. 사용자가 이해하지도 못하고 그냥 돌아가는 서비스는 로또와 다름이 없는데 말이죠.

자동화부터 하고 싶은 유혹, 있으시죠. 그거 짜기 전에 직접 로직을 이해는 해보셨나요?
```

**자답(1/n)** — 발행 직후 30분 내에 직접 단다:

```
"손으로 돌린다"가 막연하면: 케이스마다 실제 리뷰를 읽고, 5단계(수집 → 시장 성숙도 → 기회 점수 → 앵글 생성 → 반응 검증)를 종이에 직접 계산했습니다.

기회 점수는 O = I + max(I − S, 0). I는 그 요소의 중요도, S는 시장이 이미 만족시킨 정도입니다. 14번째 케이스에서도 새 결함이 나왔다면 코드는 더 미뤘을 겁니다.
```
