# 개인정보처리방침 고지 문구 초안 — 아이디어 질의 저장 (초안, 미적용)

- 작성: 2026-10-01, 앵글 검증(`/cases/report` I4) 구현 PR 과 함께. **화면·약관에 아직 넣지 않았다.** 적용 여부·문구 확정은 남헌.
- 배경: 남헌 2026-10-01 확정 2 — 로그인 사용자가 앵글 검증을 요청할 때 넣은 아이디어 원문을 **삭제하지 않고 전부 저장**한다(분석 목적).
- 리포 실측(2026-10-01, `grep -rn "개인정보" app docs`): **개인정보처리방침 화면·문서가 없다.** `docs/review-collection-design.md`·`docs/review-source-findings.md` 의 언급은 외부 수집 소스 점검 얘기다. 그래서 새 방침 전체가 아니라 **이 항목 하나의 초안**만 적는다. 방침 본문을 새로 만들 때 아래 절을 그대로 한 조항으로 넣으면 된다.

## 어디에 넣나 (제안)

1. 개인정보처리방침 문서(아직 없음)의 "수집 항목과 목적" 표에 한 행.
2. `/cases/report` 폼 아래 캡션(지금 "입력한 아이디어 원문은 주소(URL)에 그대로 남는다…")에 로그인후 한정으로 한 문장 — 예: "로그인 상태에서 앵글 검증을 누르면 아이디어 원문이 서비스 개선 분석용으로 저장된다. 자세한 내용은 개인정보처리방침." (방침 문서가 생긴 뒤 링크)

## 초안 문구

**수집 항목**
- 앵글 검증을 요청할 때 입력한 아이디어 원문 텍스트
- 요청한 계정의 이메일 주소(로그인 계정)
- 요청 시각, 요청 결과 구분(새 실행 · 이전 결과 재사용 · 사용 한도 · 실패)

**수집 방법**
- 로그인한 사용자가 `/cases/report` 에서 앵글 검증을 요청할 때 서버가 자동으로 기록한다.
- 로그인하지 않은 방문자가 입력한 아이디어는 이 기록에 저장하지 않는다(주소(URL)·접속 기록에는 남을 수 있다 — 기존 고지 그대로).

**이용 목적**
- 창업자들이 어떤 주제를 고민하는지, 그 주제들의 비율이 어떻게 바뀌는지 분석해 서비스(케이스 수집 방향·기능 우선순위)를 개선한다.
- 같은 아이디어를 다시 요청했을 때 이전 결과를 바로 보여준다(7일).

**보관 기간**
- 영구 보관한다(자동 삭제하지 않는다).
- 삭제 요청 절차: **[남헌이 정함 — 비워 둠]** (예: 문의 이메일 ____ 로 요청하면 ___일 안에 해당 계정의 기록을 삭제한다. 이 부분은 지어내지 않았다.)

**제3자 제공**
- 제3자에게 제공하지 않는다.

**처리 위탁**
- 앵글 문구 생성·판정을 위해 아이디어 원문이 **Anthropic(Claude)** 으로 전송된다(수탁자: Anthropic, 위탁 업무: AI 문장 생성·판정). 요청 시점에 한 번 보내며, 이 서비스가 Anthropic 에 별도로 저장을 요청하지 않는다. **[Anthropic 측 보관·학습 여부는 계정 계약 조건 확인 후 적는다 — 확인 전이라 비워 둠]**
- 데이터베이스는 Supabase(수탁자), 서버는 Vercel(수탁자)에서 처리된다. **[기존에 이 둘을 고지한 문서가 없다 — 방침 작성 시 함께 적을지 남헌 결정]**

## 남헌이 정할 것
- 삭제 요청 창구와 처리 기한.
- 방침 문서를 어디에 둘지(공개 화면 `/privacy` 신설 여부 — 신설하면 `lib/auth/policy.ts` `PUBLIC_EXACT` 에 넣어야 해서 §10.2 예외 3번 판단이 필요하다).
- 익명 방문자의 `/cases/report?q=` 질의를 서버 DB 에 저장하는 것은 **이번 범위가 아니다(미구현)** — 저장하려면 프라이버시 범위가 달라지므로 별도 결정.
