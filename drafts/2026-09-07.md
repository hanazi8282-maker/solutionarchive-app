## 1. 왜 코드 짜기 전에 손으로 14번 돌렸나

- 소재: `T3-1` (T3) 왜 코드 짜기 전에 손으로 14번 돌렸나
- 가설: `H3` 발행 후 1시간 내 자답글이 확산 배수를 올린다 (변수: self_reply)
- 패턴: 3
- 훅: 고백형
- 마무리: 열린질문
- 주제 태그: #빌드인퍼블릭
- 길이: 308자 / 500
- 메모: LOG-20260907-02. 방법론 정체성 글. H3(자기답글 30분내 → 확산). 근거: HANDOVER-SEED §2-1. 게이트: drafts/threads/2026-09-07-t3-1-hand-before-code.md

```
코드를 한 줄도 안 짜고, 만들던 로직을 손으로 14번 돌렸습니다.

리뷰에서 소구점을 뽑아내는 자동화를 만들고 있었는데, 엔진을 짜기 전에 먼저 종이 위에서 돌렸습니다. 서로 다른 13개 업종, 14개 케이스를요.

이유는 하나였습니다. 코드로 만들면 틀려도 그럴듯하게 돌아갑니다. 손으로 하면 어디서 억지가 들어가는지 몸으로 압니다.

14번을 돌리고 나니 결함이 나온 자리가 전부 가장자리였습니다. 뼈대는 안 틀렸다는 뜻이었고, 그때 코드를 짜기 시작했습니다.

자동화부터 하고 싶은 유혹, 있으시죠. 그거 짜기 전에 손으로 몇 번 돌려보셨나요?
```

**자답(1/n)** — 발행 직후 30분 내에 직접 단다:

```
"손으로 돌린다"가 막연하면: 케이스마다 실제 리뷰를 읽고, 5단계(수집 → 시장 성숙도 → 기회 점수 → 앵글 생성 → 반응 검증)를 종이에 직접 계산했습니다.

기회 점수는 O = I + max(I − S, 0). I는 그 요소의 중요도, S는 시장이 이미 만족시킨 정도입니다. 14번째 케이스에서도 새 결함이 나왔다면 코드는 더 미뤘을 겁니다.
```
