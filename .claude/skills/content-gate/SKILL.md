# content-gate

솔파(윤성원, 유튜브 롱폼)와 프드프(자청·이상한마케팅, 인스타 릴스) 두 방법론을
하나의 게이트로 통합해 실행한다. 초안 하나에 게이트를 두 번 돌리지 않는다.

정본은 `methodology/content/` 이고, 이 스킬의 `references/` 는 그 복사본이다
(동기화: `bash scripts/sync-content-skill.sh`, 드리프트 검사: `--check`).
`01-methodology.md`(각 300KB 초과)와 `05-provenance.md`는 references에 없다.
본문 §번호를 파고들어야 하면 정본 `methodology/content/<solfa|pdp>/01-methodology.md`를 직접 연다.

## 정방향 (내 초안 검증)

`references/00-gate.md`의 4단계를 순서대로 실행한다. 매체별 게이트를 두 개 다 돌리지 않는다.

**Ⅰ. 공통 관문 3항목** — 매체 무관. 여기서 떨어지면 다른 검토 없이 반려한다.
- U-1 타깃 (C-01) / U-2 구조 (C-12) / U-3 관찰 (C-08)
- 이 셋은 솔파와 프드프가 완전히 일치한 항목이다. 가장 강한 규칙이다.

**Ⅱ. 조건 분기 5개** — D-1~D-5 표를 조회해 어느 쪽 규칙을 쓸지 결정한다.
- Threads·릴스·숏폼 → 기본값 프드프
- 유튜브 롱폼·브랜디드 → 기본값 솔파
- 결정한 이유를 한 줄로 명시한다

**Ⅲ. 매체별 게이트** — 한쪽만 돈다.
- 프드프면 `references/pdp-gate.md` G-0~G-13
- 솔파면 `references/solfa-gate.md` G-0~G-10
- ★ Ⅰ에서 이미 본 항목은 건너뛴다 (pdp G-3·G-7 / solfa G-2·G-4)
- 규칙 충돌 시 `references/pdp-decisions.md`(P-01~P-14) 또는
  `references/solfa-decisions.md`(R-01~R-14)를 적용한다
- 구조가 막히면 `references/pdp-excerpts.md` 또는 `references/solfa-excerpts.md`의
  반례·원리·before/after에서 제안한다

**Ⅳ. 충돌 3건** — X-1(감·재능) / X-2(알고리즘) / X-3(진위)를 만나면
판정하고 **반드시 기록**한다. 이게 이 아카이브의 유일한 학습 입력이다.
세 충돌의 정의와 양쪽 입장은 `references/cross-decisions.md`의 미해결 충돌 절에 있다.

**Ⅴ. 로그** — 출력 마지막에 판정 로그 엔트리를 복사 가능한 코드블록으로 제시한다.
`출처`(자체발행/외부관찰), `방법론`(솔파/프드프/교차), **예측** 필수.
예측이 없으면 D+30에 아무것도 학습되지 않는다.

## 역방향 (남의 콘텐츠 분석)

★ 정방향과 결정적으로 다르다: **양쪽 게이트를 다 돌린다.**

1. Ⅰ의 3항목을 역방향으로 묻는다
2. 매체에 맞는 쪽의 G-R 질문표를 채운다 — 댓글·인용문 실물로.
   추측으로 채우면 의미 없음을 알린다
3. **핵심 판정 2개**를 낸다:
   - 솔파 게이트로 탈락시켰겠는가?
   - 프드프 게이트로 탈락시켰겠는가?
4. 결과 처리:
   - 둘 다 통과 → 신뢰도 +1
   - 둘 다 탈락 → ★ 양쪽 공통 구멍. 최고 가치. 신규 규칙 후보
   - **한쪽만 탈락 → ★★ 조건부 규칙의 증거. cross-decisions.md 갱신 대상**

G-R 질문표는 양쪽에 다 있다 — `references/solfa-gate.md` G-R,
`references/pdp-gate.md` G-R. 질문표 행 번호는 각 게이트 항목(G-x)에 1:1로 대응한다.

역방향 엔트리 템플릿은 `references/<자료>-decisions.md`의 `역방향 엔트리 템플릿`에 있다.
`출처: 외부관찰` 플래그를 반드시 단다. `구멍` 결론이면 `## 5. 신규 규칙 후보`에
`발견 경로: 외부관찰(G-R 구멍)`로 엔트리를 함께 만든다.

## 평가 모드

"몇 점", "평가 세트", "내 판정 실력"을 물으면 정본 `methodology/content/eval-set.md`의
§2 문항만 제시하고 사용자 답변을 받은 뒤 §3으로 채점한다.
§4 채점표의 규칙별 약점 진단까지 낸다. 문항과 함께 정답을 먼저 보여주지 않는다.

## 공통 금지

- 게이트 항목을 건너뛰지 않는다
- 통과 여부를 애매하게 남기지 않는다 (통과/탈락/예외통과 셋 중 하나)
- Ⅰ에서 떨어졌는데 문장을 다듬어 주지 않는다. 기획으로 되돌아갈 §번호를 지시한다
- 매체별 게이트를 두 개 다 돌리지 않는다 (역방향은 예외)
- 예외통과는 항목을 명시하고 신규 규칙 후보로 기록한다

## 로그 기록

판정 로그를 실제로 파일에 남길 때는 **정본**에 append 한다. `references/` 복사본에 쓰지 않는다.

- 프드프 판정 → `methodology/content/pdp/04-decisions.md`의 `## 4. 판정 로그`
- 솔파 판정 → `methodology/content/solfa/04-decisions.md`의 `## 4. 판정 로그`
- 교차/충돌(X-1~X-3) → `methodology/content/cross-decisions.md`

`## 2. 규칙 SEED`는 수정 금지 — 갱신은 `## 3. 규칙 갱신 이력`에 append.
정본을 고쳤으면 `bash scripts/sync-content-skill.sh`로 references를 맞춘다
(pre-commit hook이 자동으로 검사한다).
